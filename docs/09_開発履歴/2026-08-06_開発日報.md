## 2. 犬猫登録

ブリーダーが以下の情報を登録できるようにした。

- 管理名
- 公開表示名
- 犬猫種別
- 犬種・猫種
- 性別
- 誕生日
- 毛色
- 性格
- 価格
- 価格補足

新規登録時は必ず以下とする。

- status = draft
- display_order = 0
- breeder_id はログインユーザーからサーバー側で取得
- クライアントから breeder_id を受け取らない

## 3. 犬猫編集

以下のURLで登録済み情報を編集可能にした。

/breeder/pets/[petId]/edit

他ブリーダーの犬猫は取得・更新できない設計とした。

statusは基本情報編集画面から変更しない。

## 4. 写真管理

Private Storageとして以下を作成した。

Bucket:

pet-photos

設定：

- public = false
- 最大10MB
- image/jpeg
- image/png

Storage path：

breeders/{authUserId}/pets/{petId}/{uuid}.{extension}

元ファイル名はStorage pathに使用しない。

写真情報は `public.pet_photos` に保存する。

最初の写真は以下とする。

- is_main = true
- display_order = 0

写真表示には公開URLではなくSigned URLを使用する。

## 5. 発生した問題

### 問題1：犬猫登録時の外部キーエラー

以下のエラーが発生した。

insert or update on table "pets"
violates foreign key constraint
"pets_breeder_id_fkey"

### 原因

`pets.breeder_id` の外部キー参照先が誤っていた。

誤：

pets.breeder_id
→ auth.users.id

正：

pets.breeder_id
→ public.breeders.id

アプリケーション側では、

auth.users.id
↓
public.breeders.user_id
↓
public.breeders.id

と正しく変換していた。

Repository・Serviceは正常であり、DB側の外部キー定義が原因だった。

### 解決方法

`pets_breeder_id_fkey` を削除し、

public.breeders(id)

を参照する外部キーとして再作成した。

修正後、犬猫登録に成功した。

### 教訓

外部キーエラー発生時は、アプリケーションコードだけでなく、DBの実際の制約定義を早い段階で確認する。

確認順：

1. DBテーブル定義
2. 外部キー
3. RLS
4. Repository
5. Service

PostgreSQLの `pg_constraint` を使用すると、実際の参照先を正確に確認できる。
