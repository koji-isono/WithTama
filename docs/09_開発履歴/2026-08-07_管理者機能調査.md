## 2. 管理者 role の管理方法

### auth.users の metadata

| 用途                     | 使用箇所                      | 内容                             |
| ------------------------ | ----------------------------- | -------------------------------- |
| **`user_metadata.role`** | アプリ認証（`parseUserRole`） | `"buyer"` / `"breeder"` のみ受理 |
| **`app_metadata.role`**  | DB の `public.is_admin()`     | `'admin'` で管理者判定           |

**アプリと DB で参照 metadata が不一致。**

```typescript
// src/features/auth/types.ts
export function parseUserRole(user: User): UserRole | null {
  const role = user.user_metadata?.role;
  if (role === "buyer" || role === "breeder") {
    return role;
  }
  return null;
}
```

```sql
-- supabase/migrations/20260804135800_create_breeders.sql
CREATE OR REPLACE FUNCTION public.is_admin()
...
  SELECT coalesce(
    (auth.jwt() -> 'app_metadata' ->> 'role') = 'admin',
    false
  );
```

### public テーブルに管理者情報

- **`admins` テーブル等は存在しない**（Migration・grep ともに該当なし）
- 管理者は Supabase Auth の `app_metadata.role` 前提（Migration コメント: `docs/07_権限設計` 参照）

### UserRole 型

| ファイル                     | 定義                                          |
| ---------------------------- | --------------------------------------------- |
| `src/types/domain.ts`        | `"buyer" \| "breeder" \| "admin"`             |
| `src/features/auth/types.ts` | `"buyer" \| "breeder"` のみ（**admin なし**） |

### 管理者判定関数

| 場所                 | 有無                           |
| -------------------- | ------------------------------ |
| DB                   | `public.is_admin()` — **あり** |
| アプリ（TypeScript） | **`isAdmin` 等は未実装**       |

### サインアップ・ログイン

- サインアップ: `buyer` / `breeder` のみ（`src/lib/supabase/sign-up.ts`）
- ログイン後遷移: `getPostLoginPath` は `/buyer` または `/breeder` のみ（admin パスなし）
- `ensureUserProfile` は admin 非対応 → admin 相当ユーザーは現状ログインフローで `InvalidUserRoleError` になる

### Service Role Client

- `src/lib/supabase/admin.ts` に `createAdminClient()` あり
- **コードベース内で未使用**（定義のみ）

## 3. 管理者ルートガード

### middleware

**存在しない。** ルート単位の一括ガードなし。

### ロール別ガード（現状）

| ルート                  | 認証                      | role 判定  | 備考                                         |
| ----------------------- | ------------------------- | ---------- | -------------------------------------------- |
| `/breeder`              | ✅                        | ✅ breeder | `getBreederEntryPath()`                      |
| `/buyer`                | ✅                        | ✅ buyer   | `getBuyerEntryPath()`                        |
| `/admin`                | ❌                        | ❌         | ガードなし                                   |
| `/breeder/dashboard` 等 | ❌                        | ❌         | layout にもガードなし（モック表示可能）      |
| `/breeder/pets` 等      | Server Action / loader 内 | 間接的     | 未ログインはエラーメッセージ or `notFound()` |

### Server Component 側の権限制御

- **入口ページ**（`/breeder`, `/buyer`）のみ Server 側で redirect
- **ブリーダー layout**（`src/app/breeder/layout.tsx`）は UI のみ、認証チェックなし
- 犬猫一覧 `loadBreederPets()` は Server 側で `auth.getUser()` → 未ログインは `{ success: false }`
- 犬猫編集 `loadPetEditPageData()` は未ログインで `null` → **`notFound()`（404）**。`/login` へは飛ばさない

### Client Component のみの権限判定

- ログインページは Client Component だが、**権限の最終判定は Server Action / loader 側**でも実施
- admin 向け Client 側判定は存在しない

### 申請日時について

- `pets` に `submitted_at` / `review_requested_at` 等は **未定義**（`docs/05_データベース設計/pets.md` にもなし）
- `submitPetForReview` は `status: under_review` と **`updated_at` を明示更新**（`updated_by` も設定）

```typescript
// src/features/pets/repository.ts — submitPetForReview
.update({
  status: "under_review",
  updated_by: updatedBy,
  updated_at: new Date().toISOString(),
})
```

→ **現状は `updated_at` を申請日時の代替として使えるが、他 UPDATE でも `updated_at` が変わるため、審査用途としては不十分な可能性が高い。** 専用カラム要否は設計未決定。

## 8. セキュリティ上の懸念

根拠付きで列挙。

1. **`/admin` に認証・role ガードがない** — 誰でもアクセス可能（現状はプレースホルダーのみだが、審査機能追加時にそのままでは危険）

2. **`pets` RLS が開発用全許可のまま** — `001_pets.sql` の `pets_allow_all_for_development`。authenticated / anon 含め全操作が通る設計（Decision No.103 で本番化方針確定、Migration は未作成）

3. **admin 向け pets RLS がない** — 開発ポリシー撤去後は admin も breeder も適切に制限されない／または過剰に閉じる、のどちらかが起きうる

4. **`user_metadata.role`（アプリ）と `app_metadata.role`（DB）の不一致** — Decision No.102 で正本は `app_metadata` に確定。アプリ実装は未整合

5. **ブリーダー画面の layout レベルガードなし** — `/breeder/dashboard` 等は未認証でも表示可能

6. **admin 向け Storage RLS なし** — Decision No.104 で admin SELECT 方針確定。Migration は未作成

7. **レガシー `lib/supabase/pets.ts`** — 認証・breeder スコープなしの並存経路

8. **`createAdminClient()` の存在** — 未使用だが、審査実装時に Service Role へ逃げやすい構造
