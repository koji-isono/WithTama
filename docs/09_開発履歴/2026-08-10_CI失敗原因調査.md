## CI 失敗原因サマリー

**直接原因は ESLint error 1 件**（`react-hooks/set-state-in-effect`）。warning 7 件だけでは exit code 1 にはならない。

| ---------------------- | ------------------------------------------------------------------ |

## 1. `pet-photo-manager.tsx` の実装確認

```tsx
export function PetPhotoManager({ petId, initialPhotos }: PetPhotoManagerProps) {
  const [photos, setPhotos] = useState(initialPhotos);
  // ...
  useEffect(() => {
    setPhotos(initialPhotos);
  }, [initialPhotos]);
```

### データフロー

```
Server (edit/page.tsx)
  → loadPetEditPageData()
  → PetEditForm (initialData.photos)
  → PetPhotoManager (initialPhotos)
```

### 各操作後の更新

| 操作         | 現在の処理                                  |
| ------------ | ------------------------------------------- |
| アップロード | `router.refresh()` のみ                     |
| 削除         | `router.refresh()` のみ                     |
| メイン設定   | `setPhotos` で楽観更新 + `router.refresh()` |

`router.refresh()` 後、Server Component が再実行され `initialPhotos` は更新されるが、`PetPhotoManager` の `photos` state は **useEffect がないと古いまま** 残る。useEffect はその同期用に追加されたもの。

並び替え UI は未実装。`display_order` はサーバー側の INSERT 順に依存。

---

## 2. `initialPhotos` と `photos` の役割

| 名前            | 役割                                                             |
| --------------- | ---------------------------------------------------------------- |
| `initialPhotos` | サーバーから渡る prop（refresh 後に更新）                        |
| `photos`        | クライアントローカル state（表示・枚数カウント・メイン楽観更新） |

**二重管理**になっており、prop → state 同期のために `useEffect` + `setPhotos` を使っているのが ESLint error の原因。

---

## 3. `useEffect` 内の `setPhotos` は必要か

**現状の設計（ローカル state を維持）では必要** — upload/delete は `router.refresh()` だけなので、同期しないと一覧が更新されない。

ただし React 的には **prop を state にミラーするアンチパターン**。`react-hooks/set-state-in-effect` はまさにこれを検出している。

`eslint-disable` ではなく、**設計を変えて effect を不要にする**のが正しい修正。

---

## 4. 推奨修正案（既存動作を維持）

### 推奨: 案 A — prop を直接参照（ローカル `photos` state を廃止）

**変更内容:**

1. `const [photos, setPhotos] = useState(...)` を削除
2. `useEffect` を削除
3. 表示・枚数カウントを `initialPhotos` に統一
4. `handleSetMain` 内の楽観的 `setPhotos(...)` を削除（`pendingPhotoId` + `router.refresh()` で十分）
5. upload/delete は現状どおり `router.refresh()` のみ

**根拠（React 公式）:** [You Might Not Need an Effect — Updating state based on props](https://react.dev/learn/you-might-not-need-an-effect#updating-state-based-on-props-or-state)  
→ props から state を派生させるのではなく、props をそのまま使う。

**動作への影響:**

| 機能             | 影響                                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| 写真追加         | refresh 後に `initialPhotos` 更新 → 一覧反映 ✅                                                       |
| 写真削除         | 同上 ✅                                                                                               |
| メイン設定       | refresh 完了まで `pendingPhotoId` でボタン loading。メインバッジは refresh 後に切替（一瞬の遅延のみ） |
| 枚数上限チェック | `initialPhotos.length` で同等 ✅                                                                      |
| 並び順           | 変更なし（サーバー順のまま）                                                                          |

**変更ファイル:** `pet-photo-manager.tsx` のみ（最小 diff）

### 代替: 案 B — 親で `key` による remount

`pet-edit-form.tsx` で:

```tsx
<PetPhotoManager
  key={initialData.photos.map((p) => `${p.id}:${p.isMain ? 1 : 0}`).join("|")}
  petId={initialData.petId}
  initialPhotos={initialData.photos}
/>
```

子側は `useState(initialPhotos)` を維持し、`useEffect` のみ削除。

- refresh 後に key が変わりコンポーネントが remount → state リセット
- メイン設定の楽観更新も維持可能

**案 A の方がシンプル**。案 B は親子 2 ファイル変更になる。

### 非推奨

- `eslint-disable-next-line react-hooks/set-state-in-effect` — 回避しない
- Server Action の戻り値拡張（写真リスト返却）— 有効だが scope が大きい
