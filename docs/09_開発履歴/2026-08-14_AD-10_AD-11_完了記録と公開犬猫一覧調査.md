## 6. 次に実装すべき最小単位（提案）

### 6.1 推奨: 2 段階で進める

#### 第1段階 — 設計 + RLS 前提（Migration 1 本）

| #   | 作業                                      | 理由                                           |
| --- | ----------------------------------------- | ---------------------------------------------- |
| 1   | 画面設計 `PU-01_公開犬猫一覧.md` 作成     | 表示項目・ソート・空状態・詳細リンクを確定     |
| 2   | Decision 追記（公開写真・ブリーダー参照） | `pet_photos` / Storage / `breeders` の公開範囲 |
| 3   | Migration: 公開 SELECT ポリシー追加       | published Pet に紐づく写真・Storage 読取       |
| 4   | （必要なら）`breeders` 公開プロフィール列 | 一覧に表示する最小フィールド（例: 表示名）     |

**Service Role は使用しない。** Server Component から anon / publishable key + RLS で取得し、Signed URL は server 側で発行（既存 breeder 一覧と同パターン）。

#### 第2段階 — アプリ実装（Migration 適用後）

| #   | 作業                                               | ファイル想定                                                     |
| --- | -------------------------------------------------- | ---------------------------------------------------------------- |
| 1   | `listPublishedPetsWithMainPhoto()` repository 追加 | `src/features/pets/repository.ts` または public 用サブモジュール |
| 2   | `loadPublicPetsPage()` loader 追加                 | `src/features/pets/loaders.ts`                                   |
| 3   | 公開一覧 UI（Card）                                | `src/features/pets/components/public-pets-list.tsx`              |
| 4   | `/pets` ページ接続                                 | `src/app/(public)/pets/page.tsx`                                 |
| 5   | lint / typecheck / build                           | CI 既存ジョブで確認                                              |

**第2段階の最小スコープ:** 検索・絞り込み **なし**、published Pet の Card 一覧 + 詳細リンクのみ（プレースホルダー詳細 `/pets/[petId]` へのリンクは可。詳細本体は別工程）。

### 6.2 代替（非推奨）: RLS 追加なしのテキストのみ一覧

- `pets` の published 行のみ表示（写真・ブリーダー名なし）
- 第1期 UX として不十分なため、**第1段階（RLS）から着手することを推奨**

### 6.3 依存関係

```
Decision + PU-01 設計
    ↓
Migration（pet_photos / storage / breeders 公開 READ）
    ↓
repository / loader / UI
    ↓
/pets ページ
    ↓
（別工程）/pets/[petId] 詳細
```
