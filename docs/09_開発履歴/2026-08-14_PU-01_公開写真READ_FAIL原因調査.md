### 2.1 この ID が選ばれた理由

`scripts/test-public-pet-read.mts` の解決順:

1. `SEC_TEST_PUBLIC_PUBLISHED_PET_ID`（未設定）
2. breeder セッション探索 `discoverPetIds()` → `[SEC-TEST]` Pet のうち **最初の `status = published`**
3. `published_pets_public` View の先頭行

今回 (2) が採用された。探索結果の先頭 published が `#4`（`d07c207b-…`）のため。

**View 先頭行は使われていない**（探索 ID が優先される）。

## 5. テストコードの判定方法

```typescript
const { data: photos, error: photosError } = await anon
  .from("pet_photos")
  .select("id, storage_path, is_main")
  .eq("pet_id", resolvedPublishedPetId)
  .eq("is_main", true);

// PASS 条件: photosError == null && photos.length >= 1
```

暗黙の前提:

- 選ばれた published Pet に **`pet_photos` 行が存在する**
- そのうち **`is_main = true` の行が 1 件以上ある**

`pet_photos` 存在有無の事前チェックは **ない**。

### 6.2 参考: 同一ブリーダー配下の published `[SEC-TEST]` Pet

### 6.3 ブリーダー状態（参考）

調査時点の `SEC_TEST_REVIEW_BREEDER_ID`:

- `review_status = approved`
- `membership_status = pending`（`active` ではない）

この状態では `is_publicly_listable_pet()` は **false**、`published_pets_public` も **0 行**になりうる。  
今回の FAIL（`count=0`）については、対象 Pet に **行が無い**ことが breeder 側でも確認でき、**RLS 単独の不具合とは断定しない**。

## 7. 原因分類（A〜F）

| 分類                                                       | 該当                 | 根拠                                                                                  |
| ---------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------- |
| **A. テスト対象 published Pet に pet_photos が存在しない** | **主因**             | breeder / anon とも `d07c207b` で 0 件                                                |
| B. レコードはあるが RLS で anon から見えない               | **非該当**           | breeder でも 0 件                                                                     |
| C. pet_id と Pet ID が不一致                               | **非該当**           | 同一 ID で 0 件                                                                       |
| D. `is_publicly_listable_pet()` が false                   | **副次要因の可能性** | `membership_status = pending` 時は anon 0 件になりうるが、本 Pet は breeder でも 0 件 |
| **E. テストスクリプトの取得条件・Pet 選定が不適切**        | **副因**             | 写真なし Pet を探索先頭で選ぶ。`is_main=true` 必須だが存在チェックなし                |
| F. その他                                                  | 非該当               |                                                                                       |

**分類回答: A（主）+ E（副）**

---

## 8. 根本原因

**「RLS の不具合」ではなく「テストデータに写真がない」ことが主因。**

1. テストが選んだ `d07c207b-…` は審査 RPC 用 prepare で作成された **写真なし published Pet**。
2. `pet_photos` テーブルに **1 行も INSERT されていない**（breeder 本人 SELECT でも 0 件）。
3. テストは「published Pet ＝ 写真あり」と暗黙前提だが、Pet 選定時に `pet_photos` 有無を見ていない。

---

## 9. RLS 修正が必要か

**NO**

- 対象 Pet はデータ層で写真 0 件。
- RLS を緩めずに解決すべき問題ではない。

（別途、`membership_status` を `active` にしないと View / 公開 READ 全体が 0 行になる運用課題はあるが、**今回 FAIL の直接原因ではない**。）

---

## 10. テストデータ修正が必要か

**YES**

いずれか（または組み合わせ）:

| 対応       | 内容                                                                                                              |
| ---------- | ----------------------------------------------------------------------------------------------------------------- |
| **推奨 A** | `.env.local` に `SEC_TEST_PUBLIC_PUBLISHED_PET_ID=bb3c9725-5615-44aa-8913-286348203a41`（写真付き published Pet） |
| **推奨 B** | `d07c207b-…` に BR-11 相当で写真 1 枚アップロード（`is_main=true` になる）                                        |

| **任意 D** | テスト側で「写真付き published Pet を選ぶ」ロジック改善（別タスク）                                               |

## 11. 推奨対応

1. **SQL Editor で §12 の確認 SQL を実行**し、環境側の行数・ブリーダー状態を確定する。

3. **`SEC_TEST_PUBLIC_PUBLISHED_PET_ID`** を `bb3c9725-5615-44aa-8913-286348203a41` に設定する（または対象 Pet に写真を追加）。
4. `npm run test:public-pet-read` を再実行。

### 12.1 対象 Pet の pet_photos 有無（最重要）

### 12.2 写真付き published SEC-TEST Pet の確認

```sql
SELECT
  p.id AS pet_id,
  p.management_name,
  p.status,
  COUNT(pp.id) AS photo_count,
  COUNT(pp.id) FILTER (WHERE pp.is_main = true) AS main_photo_count
FROM public.pets p
LEFT JOIN public.pet_photos pp ON pp.pet_id = p.id
WHERE p.management_name LIKE '[SEC-TEST]%'
  AND p.status = 'published'
  AND p.deleted_at IS NULL
GROUP BY p.id, p.management_name, p.status
ORDER BY p.management_name;
```

### 12.3 `is_publicly_listable_pet()` と View 条件の整合

```sql
SELECT
  p.id AS pet_id,
  p.management_name,
  p.status AS pet_status,
  p.deleted_at AS pet_deleted_at,
  b.review_status,
  b.membership_status,
  b.deleted_at AS breeder_deleted_at,
  public.is_publicly_listable_pet(p.id) AS is_listable,
  EXISTS (
    SELECT 1 FROM public.published_pets_public v WHERE v.id = p.id
  ) AS in_public_view
FROM public.pets p
INNER JOIN public.breeders b ON b.id = p.breeder_id
WHERE p.id IN (
  'd07c207b-1017-44f7-93c7-74e663a2a25b'::uuid,
  'bb3c9725-5615-44aa-8913-286348203a41'::uuid
);
```

### 12.4 anon 相当（RLS）の確認 — postgres 権限での参照

SQL Editor（postgres）では RLS をバイパスするため、**anon 挙動の推定**用。

```sql
SELECT
  pp.id,
  pp.pet_id,
  pp.is_main,
  public.is_publicly_listable_pet(pp.pet_id) AS would_pass_rls
FROM public.pet_photos pp
WHERE pp.pet_id IN (
  'd07c207b-1017-44f7-93c7-74e663a2a25b'::uuid,
  'bb3c9725-5615-44aa-8913-286348203a41'::uuid
);
```

`would_pass_rls = true` かつ行が存在すれば、Migration 設計上 anon から SELECT 可能なはず。  
`d07c207b` で行 0 件なら **A（データ不足）**、`bb3c9725` で行あり・listable true なら RLS 設計は妥当。
