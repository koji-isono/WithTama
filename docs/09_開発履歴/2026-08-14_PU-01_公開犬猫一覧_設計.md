## 3. 既存テーブル・RLS 確認

### 3.1 `public.pets`

**Migration:** `20260807120000_harden_pets_rls.sql`

| ポリシー                       | 対象ロール          | 条件                                          |
| ------------------------------ | ------------------- | --------------------------------------------- |
| `pets_select_breeder_own`      | authenticated       | 本人所有・`deleted_at IS NULL`                |
| `pets_select_public_published` | anon, authenticated | `status = published` AND `deleted_at IS NULL` |
| `pets_select_admin`            | authenticated       | `is_admin()`                                  |

**ギャップ:** 行単位 RLS のため、anon は published 行の **全カラム**（`management_name`, `created_by` 等）を PostgREST 経由で読める。アプリ層の SELECT 列限定だけでは API 直接アクセス時の漏洩を防げない。

### 3.2 `public.pet_photos`

**Migration:** `20260806143100_create_pet_photos_table_and_rls.sql`, `20260810100000_add_admin_pet_photo_select_rls.sql`

| ポリシー                  | 対象ロール    | 条件         |
| ------------------------- | ------------- | ------------ |
| `pet_photos_select_own`   | authenticated | 本人所有犬猫 |
| `pet_photos_select_admin` | authenticated | `is_admin()` |

**anon SELECT なし** → 公開一覧でメイン写真を出すには **ポリシー追加が必須**。

### 3.3 Storage `pet-photos`

**Migration:** `20260806143000_create_pet_photos_storage.sql`, admin SELECT 追補

| 設定        | 値                            |
| ----------- | ----------------------------- |
| `public`    | **false**（private バケット） |
| anon SELECT | **なし**                      |

Signed URL 発行には Storage `SELECT` 権限が必要。**バケット public 化は採用しない**（Decision No.87 維持）。

### 3.4 `public.breeders`

**Migration:** `20260804135800_create_breeders.sql`

| ポリシー              | 条件                            |
| --------------------- | ------------------------------- |
| `breeders_select_own` | `auth.uid() = user_id` OR admin |

**設計書（breeders.md）:** 一般公開は「公開用 View または API 経由で必要項目のみ」（Decision No.44 等）。

**テーブル全体の anon SELECT は不可。**

## 6. 非公開情報（確定）

### 絶対に公開しない

- `management_name`, `breeder_id`, `user_id`, 監査カラム, 内部 `status`
- draft / under_review / paused / family_decided / closed の犬猫
- 非 published Pet の `pet_photos` および Storage オブジェクト
- 本人確認・登録証・Stripe・審査状態・電話・番地・`pet_review_logs`

### RLS 設計上の漏洩防止

| リスク                         | 対策（推奨）                                             |
| ------------------------------ | -------------------------------------------------------- |
| published Pet の内部カラム読取 | View `published_pets_public`（公開列のみ）+ GRANT anon   |
| 非 published Pet の写真読取    | `pet_photos` / Storage ポリシーで **親 Pet.status 連動** |
| breeders 全カラム読取          | View `breeder_public_profiles`（公開列のみ）             |

## 7. 写真公開方法（設計）

### 7.1 原則

1. バケット `pet-photos` は **private のまま**
2. **published かつ `deleted_at IS NULL`** の Pet に紐づく写真のみ anon / 未ログインが SELECT 可能
3. 画面表示は Server Component で **Signed URL**（既存 `PET_PHOTO_SIGNED_URL_EXPIRES_SECONDS = 300` 踏襲）
4. Service Role 不使用

### 7.2 推奨 Migration ポリシー（実装時）

#### `pet_photos` テーブル

```sql
-- 概念案（実装時に Migration ファイル化）
CREATE POLICY pet_photos_select_public_published
  ON public.pet_photos
  FOR SELECT
  TO anon, authenticated
  USING (
    EXISTS (
      SELECT 1 FROM public.pets p
      WHERE p.id = pet_photos.pet_id
        AND p.status = 'published'
        AND p.deleted_at IS NULL
    )
  );
```

#### Storage `storage.objects`

```sql
-- 概念案: パス breeders/{userId}/pets/{petId}/... と pets.id を照合
CREATE POLICY pet_photos_storage_select_public_published
  ON storage.objects
  FOR SELECT
  TO anon, authenticated
  USING (
    bucket_id = 'pet-photos'
    AND EXISTS (
      SELECT 1 FROM public.pets p
      WHERE p.id::text = (storage.foldername(name))[4]
        AND p.status = 'published'
        AND p.deleted_at IS NULL
    )
  );
```

**検証項目（実装時）:** draft Pet の写真パスを知っていても SELECT 不可であること。

### 7.3 draft / under_review 写真が漏れない理由

- ポリシー条件が **常に親 `pets.status = 'published'`** に依存
- status 変更（差戻し `under_review → draft`）後は即座に anon SELECT 不可
- バケット全体 public 化をしないため、パス推測だけではアクセス不可（RLS が必須）

### 8.1 第1期一覧に必要な最小項目

| --------------- | -------------------------------------------------------- |
| `business_name` | ✅                                                       |

### 8.2 方式比較

| 方式                          | 概要                                       | メリット                             | デメリット                           | 第1期評価 |
| ----------------------------- | ------------------------------------------ | ------------------------------------ | ------------------------------------ | --------- |
| A. breeders テーブル anon RLS | approved 行を anon SELECT 可               | 実装が単純                           | **全カラム漏洩**（phone, stripe 等） | ❌ 不採用 |
| B. PostgreSQL View            | 公開列のみ View + GRANT                    | 列制御明確、PostgREST から SELECT 可 | View + GRANT の Migration 必要       | ✅ 推奨   |
| C. SECURITY DEFINER RPC       | `list_published_pets_public()` が DTO 返却 | 1 クエリで完結                       | 新 RPC 保守、設計書外の DB API 増加  | △ 過剰    |
| D. アプリのみ JOIN + 将来 RLS | 現状のまま JOIN 不可                       | —                                    | **現状不可能**                       | ❌        |

### 8.3 推奨 View（実装時）

```sql
-- 概念案
CREATE VIEW public.breeder_public_profiles AS
SELECT
  b.id,
  b.business_name,
  b.prefecture
FROM public.breeders b
WHERE b.deleted_at IS NULL;
-- GRANT SELECT ON public.breeder_public_profiles TO anon, authenticated;
-- RLS: View に対するポリシー、または security_invoker 設定は実装時に Supabase 仕様で確定
```

**未決定:** View の `security_invoker` / 行フィルタ（`review_status = approved` を View WHERE に含めるか）は **実装 Migration 設計時** に DB 実値を確認して決定（Decision No.107 参照）。

## 9. 推奨アーキテクチャ（1 案）

### 9.1 採用案: **RLS 拡張 + 公開 View + Server Component Loader**

既存の admin / breeder 実装（Repository → Loader → Page、publishable key、Signed URL）を踏襲し、**SECURITY DEFINER RPC は第1期では作らない**。

```
[Browser] → GET /pets (no auth)
    ↓
[src/app/(public)/pets/page.tsx]  Server Component
    ↓
[loadPublicPetsPage()]  loaders.ts
    ↓
[listPublishedPetsForPublic()]  repository.ts
    ↓ Supabase JS (anon session / createClient)
    ├─ SELECT published_pets_public (+ JOIN breeder_public_profiles)  ※View 経由
    ├─ SELECT pet_photos (is_main)  ※新 RLS
    └─ storage.createSignedUrls()   ※新 Storage RLS
    ↓
[PublicPetsList]  components/public-pets-list.tsx
```

| 項目          | 方針                                      |
| ------------- | ----------------------------------------- |
| Feature 配置  | `src/features/pets/` に公開向け関数を追加 |
| 認証          | 不要                                      |
| Service Role  | 不使用                                    |
| Server Action | 不使用（読み取り専用）                    |
| API Route     | 新設しない（Server Component 直接取得）   |
| キャッシュ    | **未決定**（Next.js `revalidate` 方針）   |

### 9.2 採用しない案

| 案                             | 理由                                    |
| ------------------------------ | --------------------------------------- |
| Storage バケット public 化     | 非 published 写真の漏洩リスク、No.87 反 |
| Service Role in Server         | プロジェクトセキュリティルール反        |
| 汎用 GraphQL / BFF 新設        | 過剰設計                                |
| Client Component 直接 Supabase | 公開列制御・Signed URL 管理が分散       |

### 9.3 参考実装

| 既存                                   | 流用点                           |
| -------------------------------------- | -------------------------------- |
| `listPetsWithMainPhotoByBreederUserId` | メイン写真 + Signed URL パターン |
| `admin/repository.ts` AD-10            | 一覧 + 写真 Signed URL           |
| `breeder-pets-list-content.tsx`        | Card UI（公開向けに簡素化）      |
