## 3. 公開してはいけない情報（確定）

### 犬猫

- `management_name`、内部 ID、監査カラム、非 `published` ステータス
- `ai_description`、`color`、`temperament`、`description`、`price_comment`（カード非表示）

### 写真

- 非 `published` Pet に紐づく `pet_photos` / Storage オブジェクト
- バケット全体の public 化

### ブリーダー

- `user_id`、`phone`、詳細住所、書類パス、Stripe、審査状態、登録証情報

### その他

- `pet_review_logs`、認証ユーザーのメールアドレス等

### 既存 RLS ギャップ

`pets_select_public_published` は行単位のため、PostgREST 直接アクセスでは `management_name` 等も読める。**View `published_pets_public`（公開列のみ）の追加を推奨。**

---

## 4. 写真公開方法（確定）

| 項目     | 方針                                                                   |
| -------- | ---------------------------------------------------------------------- |
| バケット | `pet-photos` は **private 維持**（public 化しない）                    |
| RLS      | 親 Pet が `published` かつ `deleted_at IS NULL` のときのみ anon SELECT |
| 表示     | Server Component で Signed URL（Decision No.87 踏襲）                  |
| 漏洩防止 | draft / under_review 等の写真は RLS 条件で除外                         |

**追加ポリシー（実装時）:**

- `pet_photos_select_public_published`（テーブル）
- `pet_photos_storage_select_public_published`（Storage）

---

## 6. 推奨アーキテクチャ（1案）

**RLS 拡張 + 公開 View + Server Component Loader**

```
/pets (Page)
  → loadPublicPetsPage()
  → listPublishedPetsForPublic()
  → View + pet_photos RLS + createSignedUrls()
  → PublicPetsList (Card UI)
```

| 項目          | 方針                                    |
| ------------- | --------------------------------------- |
| Feature       | `src/features/pets/` に公開向け関数追加 |
| 認証          | 不要                                    |
| Service Role  | 不使用                                  |
| Server Action | 不使用（読み取り専用）                  |
| 新 RPC        | 作らない                                |

**参考実装:** `listPetsWithMainPhotoByBreederUserId`、AD-10 admin repository、`breeder-pets-list-content.tsx`
