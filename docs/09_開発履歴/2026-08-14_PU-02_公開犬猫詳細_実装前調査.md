## 4. 写真公開方式

### 4.1 現行設計（Migration 適用済み）

| 層               | 内容                                                                      |
| ---------------- | ------------------------------------------------------------------------- |
| `pet_photos` RLS | `pet_photos_select_public_published` — `is_publicly_listable_pet(pet_id)` |
| Storage RLS      | `pet_photos_storage_select_public_published` — 同上 + パス検証            |
| バケット         | `pet-photos` **private**                                                  |
| 表示             | Server Component で **Signed URL**（300 秒）                              |

### 4.2 複数写真の安全な表示

| 観点                               | 判定                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------ |
| 複数 `pet_photos` 行の anon SELECT | **可能** — RLS は `pet_id` 単位。公開条件を満たす Pet なら **全写真行** が対象 |
| `display_order` / `created_at` 順  | **可能** — 列自体は SELECT 可（`storage_path` は HTML 非露出）                 |
| `is_main`                          | メイン強調表示に利用可                                                         |
| `alt_text`                         | 公開可（アクセシビリティ）                                                     |
| 他 Pet の写真                      | **不可** — `is_publicly_listable_pet` が false                                 |
| Signed URL バッチ                  | PU-01 `createSignedUrls` パターンを **全 storage_path** に拡張即可             |

**結論: PU-02 で複数写真ギャラリーは、既存 RLS / Storage ポリシーのまま安全に実装可能。**

## 6. `published_pets_public` と View 拡張の比較

### 6.1 現在の View 列

```
id, public_display_name, species, breed, sex, birthday, price, breeder_id
```

### 6.2 PU-02 詳細に不足する Pet 列

| 不足列          | 用途               |
| --------------- | ------------------ |
| `color`         | 基本情報           |
| `temperament`   | 性格セクション     |
| `description`   | 「この子について」 |
| `price_comment` | 価格補足           |

### 6.3 不足する Breeder 列（別 View）

`profile_text`, `breeding_policy`, `health_policy`, `breeding_environment`, `city`（+ 任意 `website_url`, `public_email`）

### 6.4 方式比較

| 方式                         | 内容                                                                | メリット                  | デメリット                                             |
| ---------------------------- | ------------------------------------------------------------------- | ------------------------- | ------------------------------------------------------ |
| **A. 既存 View 拡張**        | `published_pets_public` / `breeder_public_profiles` に列追加        | Migration 1 本で済む      | 一覧用 View が詳細列を含む（SELECT 列指定で Mitigate） |
| **B. 詳細専用 View 新設**    | 例: `published_pet_detail_public`, `breeder_public_detail_profiles` | 一覧/詳細の責務分離が明確 | Migration で View 2 本追加。JOIN 条件の重複管理        |
| **C. その他（apps 層のみ）** | View 不变、`pets` 直接 SELECT                                       | なし                      | **anon が内部列を読めるため不可**                      |

### 6.5 推奨案: **B（詳細専用 View 新設）**

理由:

1. PU-01 一覧 View は **最小列のまま維持**（設計意図の明確化）
2. 詳細列（長文 `description` 等）を一覧 API 経路と分離
3. 公開条件（`published` + approved + active + not deleted）は **同一 WHERE 句をコピー** し、`is_publicly_listable_pet` / 既存 View と整合
4. RLS 緩和不要（View は `security_invoker = false` + GRANT SELECT のみ）

**Migration は PU-02 実装フェーズで 1 本新規作成**（今回は設計のみ）。

## 7. 公開条件と直接 URL アクセス

### 7.1 `is_publicly_listable_pet()` / View 条件（すべて AND）

| #   | 条件                                    |
| --- | --------------------------------------- |
| 1   | `pets.status = 'published'`             |
| 2   | `pets.deleted_at IS NULL`               |
| 3   | `breeders.deleted_at IS NULL`           |
| 4   | `breeders.review_status = 'approved'`   |
| 5   | `breeders.membership_status = 'active'` |

### 7.2 Decision No.107 との関係

No.107 は **管理者承認時** の前提（`identity_verification_status = verified` 等）。  
公開 READ View は **`review_status = approved` + `membership_status = active`** を使用（PU-01 Migration 確定済み）。  
承認済みブリーダーは通常 verified だが、**View 条件と No.107 条件は 1:1 ではない** — 実装時も View を正とする。

### 7.3 非公開 Pet への直接 URL

| ケース                           | View / RLS 挙動  | アプリ方針                                  |
| -------------------------------- | ---------------- | ------------------------------------------- |
| draft / under_review / paused 等 | View **0 行**    | `notFound()`                                |
| published だが breeder pending   | View **0 行**    | `notFound()`                                |
| suspended / canceled breeder     | View **0 行**    | `notFound()`                                |
| 論理削除 Pet                     | View **0 行**    | `notFound()`                                |
| 存在しない UUID                  | View **0 行**    | `notFound()`                                |
| 不正 UUID 形式                   | PostgREST エラー | `notFound()` またはエラー表示（**未決定**） |

**設計原則:** 詳細取得は **`published_pet_detail_public`（新 View）への `.eq('id', petId).maybeSingle()` のみ**。0 行なら **404**。`pets` テーブル直接 SELECT は使わない。

| private Storage 直接参照不可        | Signed URL のみ。public URL 不使用                        |
| 他 Pet の非公開写真                 | `is_publicly_listable_pet(pet_id)` で拒否（**適用済み**） |
| `breeder_id` HTML 露出              | DTO / JSX に出力しない                                    |
| `storage_path` HTML 露出            | Signed URL のみ出力                                       |
| Service Role                        | **使用禁止**（公開画面）                                  |
