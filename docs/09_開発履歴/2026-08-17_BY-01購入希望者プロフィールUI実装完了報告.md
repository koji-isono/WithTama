## 5. Loader / 初期データ

`loadBuyerProfilePageData()`（`src/features/buyers/loaders.ts`）

1. `requireBuyer()` で buyer 本人を確定
2. `getBuyerProfileByUserId(user.id)` で本人プロフィール取得（RLS）
3. `email` は Supabase Auth `user.email`（buyers テーブルからは取得しない）
4. `mapBuyerProfileRowToInput()` でフォーム初期値に変換

## 6. UI

`BuyerProfileForm`（スマートフォン優先・WithTama 既存コンポーネント）

| セクション     | 項目                                                               |
| -------------- | ------------------------------------------------------------------ |
| Header         | `SiteHeader` + ページタイトル + 説明文                             |
| 基本情報       | 氏名・表示名・メール（read only）・電話・都道府県 select・市区町村 |
| 希望・自己紹介 | 自己紹介・希望する種類 select・希望する犬種・猫種                  |
| 通知設定       | `notification_enabled` チェックボックス                            |
| 保存           | 全幅ボタン                                                         |

**表示禁止項目:** `user_id` / `buyer_id` / `membership_status` / `profile_completed` / タイムスタンプ類は UI に出さない

**都道府県:** `JAPAN_PREFECTURES`（select）

**希望する種類:** 未選択 → null 相当、犬 → `dog`、猫 → `cat`、犬・猫どちらも → `both`

## 7. 保存処理

- Client: `buildFormData()` で許可フィールドのみ FormData 構築（PII ID 不含）
- Server Action: 既存 `saveBuyerProfileAction` をそのまま利用
- 保存中: `isSubmitting` で二重送信防止・ボタン disabled・「保存中...」表示
- validation error: フィールド近傍 + クライアント側入力値維持
- form error: フォーム上部 Alert
- 成功: Action 内 redirect なし → `router.push("/buyer/dashboard")`

---

## 8. profile_completed

- UI から直接操作不可（hidden input もなし）
- データ層の Server 側算出（`buildUpdateBuyerProfileData`）をそのまま使用
- 初回/編集でページタイトル・説明文のみ切替（`profileCompleted` は表示専用）
