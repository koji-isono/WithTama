## 7. RLS・権限

### 7.1 `public.buyers` ポリシー（Migration 実体）

| ポリシー            | 操作     | 条件                                         |
| ------------------- | -------- | -------------------------------------------- |
| `buyers_select_own` | SELECT   | `auth.uid() = user_id`                       |
| `buyers_insert_own` | INSERT   | `auth.uid() = user_id`                       |
| `buyers_update_own` | UPDATE   | `auth.uid() = user_id`（USING / WITH CHECK） |
| DELETE              | **なし** | 物理削除不可                                 |
| admin SELECT        | **なし** | `is_admin()` ポリシーなし                    |
| breeder SELECT      | **なし** | 問い合わせ当事者でも不可                     |

**「本人だけ READ/UPDATE」:** ✅ Migration 上は成立。

### 7.2 問い合わせ系 RLS（buyer 視点）

| テーブル           | buyer 操作           | 要点                                               |
| ------------------ | -------------------- | -------------------------------------------------- |
| `inquiries`        | SELECT/INSERT/UPDATE | `buyers.user_id = auth.uid()` かつ `buyer_id` 一致 |
| `inquiry_messages` | SELECT/INSERT/UPDATE | 関連 inquiry の当事者                              |
| `visits`           | SELECT/INSERT/UPDATE | `buyer_id` が本人                                  |
| `favorites`        | SELECT/INSERT/DELETE | `buyer_id` が本人                                  |

`inquiries_insert_buyer` は `pet.status = published` 等を WITH CHECK。**`profile_completed` は RLS 条件に含まれない**。

### 7.3 ロール判定

| 用途          | 正本                            | 実装                           |
| ------------- | ------------------------------- | ------------------------------ |
| buyer/breeder | `user_metadata.role`            | `parseMemberUserRole`          |
| admin         | `app_metadata.role === "admin"` | `isAdminUser` / `requireAdmin` |

## 9. セキュリティ確認

| 確認項目                                            | 結果        | 備考                                                          |
| --------------------------------------------------- | ----------- | ------------------------------------------------------------- |
| 他ユーザーの `buyers` を anon/authenticated が READ | ✅ 不可     | `buyers_select_own` のみ                                      |
| 他ユーザーの `buyers` を UPDATE                     | ✅ 不可     | `buyers_update_own`                                           |
| buyer PII が public View に含まれる                 | ✅ なし     | 公開 View に buyers 未参加                                    |
| Service Role をブラウザで使用                       | ✅ なし     | `createAdminClient` は `server-only`。buyer 経路から未 import |
| RLS 迂回                                            | ✅ 現状なし | buyer feature 未実装のため UPDATE 経路自体なし                |
| 問い合わせ経由の PII 公開                           | ⚠️ 未設計   | ブリーダーが buyer 連絡先をどう取得するか **RLS 上未解決**    |
| `/buyer/profile` 未認証アクセス                     | ⚠️ ギャップ | プレースホルダーは認証ガードなし。実装時に Server ガード必須  |
| bootstrap が Client 実行                            | ℹ️ 既存     | breeder と同パターン。JWT + RLS で INSERT                     |

**懸念（実装時に Decision 化推奨）:**

- ブリーダーへの buyer 連絡先開示: 追加 RLS / SECURITY INVOKER View / inquiry 作成時スナップショットのいずれか
- 問い合わせ送信時の `profile_completed` 必須化（アプリ層 vs RLS）
- `auth.users.email` を BY-01 に表示する場合の取得経路（Server の `getUser()` のみ。DB 露出しない）
