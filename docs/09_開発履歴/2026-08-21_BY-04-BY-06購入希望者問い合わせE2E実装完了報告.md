## 原子性・整合性（Decision 整合）

新規 RPC / migration は **追加・適用していない**。

| 処理                    | 方式                                                           |
| ----------------------- | -------------------------------------------------------------- |
| 初回問い合わせ（BY-04） | inquiry INSERT → message INSERT → `last_message_at` UPDATE     |
| message 失敗時          | `inquiries.deleted_at` で論理削除（ロールバック）              |
| 競合（重複 inquiry）    | 古い inquiry を canonical とし、新規分を soft delete           |
| 追加メッセージ（BY-06） | message INSERT → `last_message_at` UPDATE（単一 message のみ） |

**残るリスク:** inquiry 作成成功後、`last_message_at` UPDATE 失敗時にタイムスタンプのみ不整合の可能性（message 自体は存在）。第1期は許容。完全原子化には DB 関数 / トランザクション RPC が必要だが、今回は migration 未適用方針のため Server 側 best-effort。
