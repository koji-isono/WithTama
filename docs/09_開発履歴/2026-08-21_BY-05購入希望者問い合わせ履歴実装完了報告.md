## 6. 認証・認可

- `(buyer)/layout.tsx` の `requireBuyer()` — 未ログインは `/login` へ
- buyer 以外は既存アクセス制御ルールで拒否
- `requireBuyer()` → `getBuyerProfileByUserId(user.id)` → `buyer.id` を Server 側で確定
- クライアントから `buyer_id` / `user_id` は受け取らない

---

## 7. 問い合わせ取得条件

```
inquiries.buyer_id = ログイン buyer.id
AND inquiries.deleted_at IS NULL
```

**status による除外なし** — `open` / `replied` / `visit_requested` / `visit_scheduled` / `completed` / `closed` すべて一覧対象。

---

## 8. 並び順

1. `last_message_at DESC NULLS LAST`
2. 同値または NULL 時は `created_at DESC`

---

## 9. pet 情報取得方法

- **公開中:** `listPublishedPetsForPublicByIds()` で写真・名称・ブリーダー名を一括取得
- **非公開:** `extractPetNameFromInquirySubject()` で件名から名称を復元、写真はプレースホルダー
- 公開 pet View のみに限定しない（Decision No.115 準拠、BY-06 と同方針）

---

## 10. breeder 情報取得方法

- 公開 pet 経由の `breederBusinessName` を優先
- 不足時は `breeder_public_profiles` を `listBreederPublicNamesByIds()` で一括取得

---

## 11. 最新 message 取得方法

`listLatestMessagesForInquiries()` で対象 inquiry のメッセージを 1 クエリ取得し、JS 側で inquiry ごとに最新 1 件を抽出。

- 表示: `truncateInquiryMessagePreview()` で **80 文字**に省略（`INQUIRY_MESSAGE_PREVIEW_MAX_LENGTH`）
- メッセージなし: 「メッセージはありません」

---

## 12. 未読判定方法

`countUnreadBreederMessagesByInquiry()` で以下を集計:

```
sender_type = 'breeder' AND is_read = false
```

- buyer 自身が送った `sender_type = 'buyer' AND is_read = false` は未読扱いしない
- 表示例: **未読 2件**（ブランドカラーの Badge）

---

## 13. ステータス表示

既存 `getInquiryStatusLabel()` / `INQUIRY_STATUS_LABELS` を BY-06 と共通利用。

| DB status       | 表示         |
| --------------- | ------------ |
| open            | 問い合わせ中 |
| replied         | 返信あり     |
| visit_requested | 見学希望     |
| visit_scheduled | 見学予定     |
| completed       | 完了         |
| closed          | 終了         |

---

## 14. 非公開 pet の扱い

公開 View に無くても問い合わせ履歴は表示。名称は subject から、写真は「写真なし」プレースホルダー。RLS 変更なし。

## 16. エラー処理

| ケース               | 対応                             |
| -------------------- | -------------------------------- |
| 未ログイン           | `/login` へ redirect             |
| buyer 以外           | 既存ルールで拒否                 |
| buyer レコード不存在 | 空一覧（エラー画面にしない）     |
| DB 取得失敗          | ユーザー向けメッセージのみ表示   |
| pet 削除/非公開      | 件名・プレースホルダーで表示継続 |
| breeder 情報欠損     | 名称非表示で継続                 |
| 写真なし             | 「写真なし」プレースホルダー     |
| message なし         | 「メッセージはありません」       |

SQL / Supabase 内部エラー / UUID / stack trace はユーザー画面に表示しない。

---

## 17. N+1 対策

固定 **5 クエリ**構成（inquiry 件数ごとの個別 SELECT なし）:

1. inquiries 一覧
2. 最新メッセージ一括
3. 未読件数一括
4. 公開 pet 一括
5. ブリーダー名一括
