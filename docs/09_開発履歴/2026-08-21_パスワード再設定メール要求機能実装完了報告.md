## 5. Supabase resetPasswordForEmail

**実装箇所（既存・再利用）:** `src/lib/supabase/reset-password-email.ts`

```typescript
export async function resetPasswordForEmail(email: string) {
  const supabase = createClient();

  return supabase.auth.resetPasswordForEmail(email, {
    redirectTo: getPasswordRecoveryRedirectUrl(),
  });
}
```

**redirectTo:** `src/lib/supabase/auth-redirect.ts` の `getPasswordRecoveryRedirectUrl()`

```
{NEXT_PUBLIC_APP_URL}/auth/callback?next=/reset-password
```

（ローカル例: `http://localhost:3000/auth/callback?next=/reset-password`）

メール内リンクは 2026-08-19 E2E 確認済みの token_hash テンプレート → `/auth/confirm` → `/reset-password` フローへ接続される。

## 6. セキュリティ上の考慮

| 項目                 | 対応                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| メールアドレス列挙   | API 応答後は **常に** 共通成功メッセージを表示（登録有無を判別不可） |
| Supabase 内部エラー  | `error.message` を画面に出さず `console.error` のみ                  |
| ネットワーク例外     | 汎用エラー「送信処理中にエラーが発生しました…」のみ表示              |
| redirectTo           | 既存 `getPasswordRecoveryRedirectUrl()` で許可 URL と一致            |
| 既存 Recovery フロー | `/reset-password` / callback / confirm は **変更なし**               |
