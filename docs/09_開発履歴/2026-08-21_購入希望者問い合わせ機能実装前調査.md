## 3. `inquiries` テーブル構造

**Migration:** `supabase/migrations/20260804163239_create_inquiries_messages_visits.sql`

| カラム            | 型          | NULL     | Default             | 説明                                  |
| ----------------- | ----------- | -------- | ------------------- | ------------------------------------- |
| `id`              | uuid        | NOT NULL | `gen_random_uuid()` | PK                                    |
| `buyer_id`        | uuid        | NOT NULL | —                   | FK → `buyers.id` ON DELETE RESTRICT   |
| `breeder_id`      | uuid        | NOT NULL | —                   | FK → `breeders.id` ON DELETE RESTRICT |
| `pet_id`          | uuid        | NOT NULL | —                   | FK → `pets.id` ON DELETE RESTRICT     |
| `status`          | text        | NOT NULL | `'open'`            | CHECK 6 値                            |
| `subject`         | text        | NULL     | —                   | 件名（任意）                          |
| `last_message_at` | timestamptz | NULL     | —                   | 最終メッセージ日時                    |
| `closed_at`       | timestamptz | NULL     | —                   | クローズ日時                          |
| `deleted_at`      | timestamptz | NULL     | —                   | 論理削除                              |
| `created_at`      | timestamptz | NOT NULL | `now()`             | 作成日時                              |
| `updated_at`      | timestamptz | NOT NULL | `now()`             | 更新日時（`set_updated_at` トリガー） |

**制約・インデックス:**

- PK: `id`
- CHECK `status`: `open` / `replied` / `visit_requested` / `visit_scheduled` / `completed` / `closed`
- INDEX: `buyer_id`, `breeder_id`, `pet_id`, `status`, `last_message_at`
- 部分 INDEX: `inquiries_active_idx`（`deleted_at IS NULL`）
- **UNIQUE 制約なし**（同一 buyer + pet の重複問い合わせを DB では防いでいない）

## 4. `inquiry_messages` テーブル構造

| カラム           | 型          | NULL     | Default             | 説明                                    |
| ---------------- | ----------- | -------- | ------------------- | --------------------------------------- |
| `id`             | uuid        | NOT NULL | `gen_random_uuid()` | PK                                      |
| `inquiry_id`     | uuid        | NOT NULL | —                   | FK → `inquiries.id` ON DELETE CASCADE   |
| `sender_type`    | text        | NOT NULL | —                   | CHECK: `buyer` / `breeder` / `admin`    |
| `sender_user_id` | uuid        | NOT NULL | —                   | FK → `auth.users.id` ON DELETE RESTRICT |
| `message`        | text        | NOT NULL | —                   | CHECK: `length(trim(message)) > 0`      |
| `is_read`        | boolean     | NOT NULL | `false`             | 既読                                    |
| `read_at`        | timestamptz | NULL     | —                   | 既読日時                                |
| `created_at`     | timestamptz | NOT NULL | `now()`             | 送信日時                                |
| `updated_at`     | —           | —        | —                   | **なし**                                |

**インデックス:** `inquiry_id`, `created_at`, 部分 INDEX（`is_read = false`）

**第1期方針（設計書）:** テキストのみ。添付なし。本文編集・物理 DELETE なし。UPDATE は既読更新のみ（**RLS 上はカラム制限なし → Server 側で制限**）。

## 5. 外部キー関係

```
auth.users
  └── buyers.user_id          inquiries.buyer_id → buyers.id
  └── breeders.user_id        inquiries.breeder_id → breeders.id
  └── inquiry_messages.sender_user_id

pets.id                       inquiries.pet_id → pets.id
                              visits.pet_id → pets.id

inquiries.id                  inquiry_messages.inquiry_id (CASCADE)
                              visits.inquiry_id (UNIQUE, RESTRICT)
```

**`inquiries` の意味（設計書・Decision No.54 より）:**

- **1 件 = 1 問い合わせ案件 / スレッド**（buyer × breeder × pet の組み合わせ）
- 本文は `inquiry_messages` に分離
- 見学は `visits` テーブル（`visits.inquiry_id` UNIQUE で 0〜1 件）
- 成約は `visits.result = 'contracted'` で表現（サイト内契約完結はしない）

**問い合わせ種別カラム:** **なし**（通常問い合わせ / 見学希望は `status` と `visits` の有無で区別）

## 6. RLS 状況

### `inquiries`（RLS 有効）

| Policy                     | 操作   | 対象    | 条件の意味                                                                                  |
| -------------------------- | ------ | ------- | ------------------------------------------------------------------------------------------- |
| `inquiries_select_buyer`   | SELECT | buyer   | `buyers.user_id = auth.uid()` かつ `buyer_id` が一致                                        |
| `inquiries_select_breeder` | SELECT | breeder | `breeders.user_id = auth.uid()` かつ `breeder_id` が一致                                    |
| `inquiries_select_admin`   | SELECT | admin   | `is_admin()`                                                                                |
| `inquiries_insert_buyer`   | INSERT | buyer   | ① 自分の `buyer_id` ② pet が `published`・未削除 ③ `pets.breeder_id = inquiries.breeder_id` |
| `inquiries_update_buyer`   | UPDATE | buyer   | 当事 buyer のみ                                                                             |
| `inquiries_update_breeder` | UPDATE | breeder | 当事 breeder のみ                                                                           |
| `inquiries_update_admin`   | UPDATE | admin   | `is_admin()`                                                                                |
| **DELETE**                 | —      | —       | **ポリシーなし（物理 DELETE 不可）**                                                        |

**不足・注意点:**

- SELECT に **`deleted_at IS NULL` フィルタなし** → 論理削除済みも当事者は読める可能性
- INSERT に **`profile_completed` チェックなし**（BY-01 設計方針と未整合）
- **第三者アクセス:** 上記ポリシーにより **不可**（migration 定義より）

### `inquiry_messages`（RLS 有効）

| Policy                          | 操作   | 条件の意味                                                  |
| ------------------------------- | ------ | ----------------------------------------------------------- |
| `inquiry_messages_select_party` | SELECT | admin、または関連 inquiry の buyer / breeder                |
| `inquiry_messages_insert_party` | INSERT | `sender_user_id = auth.uid()` かつ `sender_type` と役割一致 |
| `inquiry_messages_update_party` | UPDATE | 当事者または admin（**既読以外の更新も RLS 上は可能**）     |
| **DELETE**                      | —      | **なし**                                                    |

**セキュリティ補強推奨（今回は未修正）:**

- Server Action で UPDATE カラムを `is_read` / `read_at` のみに限定
- 他 buyer / breeder の inquiry への INSERT は RLS で拒否される設計

### `buyers` テーブル（問い合わせ関連）

- RLS: **本人 SELECT/INSERT/UPDATE のみ**
- **ブリーダーが buyer プロフィールを READ するポリシーはなし**（BY-01 着手前調査と同様）

| 概念           | テーブル           | 関係                                           |

**推奨フロー:** 通常問い合わせ送信 → （必要時）問い合わせ詳細から見学希望 — **DB 設計と整合**
