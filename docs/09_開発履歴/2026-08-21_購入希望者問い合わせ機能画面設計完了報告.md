## 4. 画面遷移

### 購入希望者

```
PU-02 犬猫詳細
  ↓「問い合わせする」
  ├─ 未ログイン → /login?next=...
  ├─ profile_completed=false → BY-01
  ├─ 有効 inquiry あり → BY-06
  └─ なし → BY-04 → 送信成功 → BY-06

BY-02 ダッシュボード → BY-05 → BY-06
```

### ブリーダー

```
BR-06 / ナビ → BR-12 一覧 → BR-12 詳細 → 返信
  ↓
購入希望者 BY-06 で確認
```

詳細 mermaid: [画面設計 README](../04_画面設計/README.md#購入希望者--問い合わせ遷移)

---

## 5. BY-04 設計概要

- 対象 pet 確認カード（写真・名称・属性・ブリーダー名）
- 入力: 問い合わせ本文のみ（`subject` 入力なし）
- 本文: 必須・空白不可・最大 **2000 文字**（**新規設計値**）
- ボタン: 「問い合わせを送信する」+ 二重送信防止
- 設計書: [BY-04](../04_画面設計/BY-04_購入希望者問い合わせ入力.md)

---

## 6. BY-05 設計概要

- 本人 inquiry 一覧（`deleted_at IS NULL` のみ）
- 並び: `last_message_at DESC NULLS LAST`（NULL 時は `created_at`）
- 表示: 写真・犬猫名・ブリーダー名・status・最終日時・概要・詳細リンク
- Empty State +「犬猫を探す」→ PU-01
- BY-02「問い合わせ履歴」接続
- 設計書: [BY-05](../04_画面設計/BY-05_購入希望者問い合わせ履歴.md)

---

## 7. BY-06 設計概要

- サマリー + メッセージ履歴（buyer/breeder 視覚区別・非チャット UI）
- 追加メッセージ送信
- `closed` / `completed` では入力不可
- 詳細表示時に相手未読を既読化
- 設計書: [BY-06](../04_画面設計/BY-06_購入希望者問い合わせ詳細.md)

---

## 8. BR-12 設計概要

- 1 ファイルに一覧・詳細を集約（README 上同一 BR-12 ID）
- 一覧: 犬猫名・buyer 表示名・status・未読 Badge・詳細リンク
- 詳細: メッセージ履歴 + 返信入力
- 初回 breeder 返信で `status → replied`
- 設計書: [BR-12](../04_画面設計/BR-12_ブリーダー問い合わせ.md)

---

## 9. 問い合わせ status 表示定義

| DB 値             | 画面表示名   | 第1期 UI 備考                            |
| ----------------- | ------------ | ---------------------------------------- |
| `open`            | 問い合わせ中 | 送信可                                   |
| `replied`         | 返信あり     | 送信可                                   |
| `visit_requested` | 見学希望     | 表示のみ（問い合わせ UI から設定しない） |
| `visit_scheduled` | 見学予定     | 同上                                     |
| `completed`       | 完了         | 送信不可                                 |
| `closed`          | 終了         | 送信不可                                 |

---

## 10. 同一 pet 再問い合わせルール

[Decision No.110](../01_設計変更管理/DecisionLog.md#decision-no110)

**有効 inquiry の定義:**

- `deleted_at IS NULL`
- `status NOT IN ('closed', 'completed')`
- 同一 `buyer_id` × `pet_id`

有効 inquiry 存在時 → **BY-06 へ遷移**（新規スレッド乱立防止）。Server 側で検索（DB UNIQUE なし）。

---

## 11. buyer 情報開示ルール

[Decision No.112](../01_設計変更管理/DecisionLog.md#decision-no112)

| 開示する       | 開示しない         |
| -------------- | ------------------ |
| `display_name` | メール・電話・住所 |

表示名取得方式（スナップショット列 / RPC）は **実装時未決定**。第1期 RLS 変更なし。

---

## 12. 既読ルール

[Decision No.116](../01_設計変更管理/DecisionLog.md#decision-no116)

- BY-06 / BR-12 詳細表示時に **相手送信分** の未読を Server で既読化
- UPDATE は `is_read` / `read_at` のみ
- Realtime 既読通知 UI なし

---

## 13. profile_completed ルール

[Decision No.114](../01_設計変更管理/DecisionLog.md#decision-no114)

- 問い合わせ開始に `profile_completed = true` **必須**
- false → BY-01 `/buyer/profile`
- Server 側で必須確認（RLS 追加なし）

---

## 14. 非公開 pet の扱い

[Decision No.115](../01_設計変更管理/DecisionLog.md#decision-no115)

| ケース         | 方針                                                   |
| -------------- | ------------------------------------------------------ |
| 新規問い合わせ | `published` + 未削除必須（Server + RLS）               |
| 既存問い合わせ | 非公開化後も **履歴閲覧・送信（status 許可時）を維持** |

---

## 15. 権限

| ロール  | 操作                                  |
| ------- | ------------------------------------- |
| buyer   | 本人 inquiry のみ閲覧・メッセージ送信 |
| breeder | 本人宛 inquiry のみ閲覧・返信         |
| admin   | RLS 上可能（第1期 UI 対象外）         |
| 第三者  | 閲覧・投稿不可                        |

---

## 16. エラー設計

未ログイン、buyer 以外、プロフィール未完了、pet 不存在/非公開、空本文、文字数超過、他人 inquiry、closed へ送信、送信失敗、二重送信、DB エラー — いずれも **汎用ユーザー向け文言**（技術詳細非表示）。
