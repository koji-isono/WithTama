# BR-12 ブリーダー問い合わせ 実装完了報告

**日付:** 2026-08-24  
**対象:** BR-12 `/breeder/inquiries`（一覧）、`/breeder/inquiries/[inquiryId]`（詳細・返信）

---

## 1. 結論

**BR-12「ブリーダー問い合わせ」**を実装し、ブリーダーが購入希望者からの問い合わせを **確認・返信** できる導線を完成した。新規テーブル追加・RLS 変更・Service Role 利用は行っていない。

---

## 2. 実装 URL

| 画面                 | URL                              | 種別                       |
| -------------------- | -------------------------------- | -------------------------- |
| 問い合わせ一覧       | `/breeder/inquiries`             | 表示                       |
| 問い合わせ詳細・返信 | `/breeder/inquiries/[inquiryId]` | 編集 URL（Decision No.72） |

サイドバー / モバイルナビの「問い合わせ」リンク（`/breeder/inquiries`）は既存設定のまま利用可能。

---

## 3. 認証・認可

| 項目             | 内容                                                      |
| ---------------- | --------------------------------------------------------- |
| 認証             | `requireBreeder()`（`src/features/auth/breeder-auth.ts`） |
| 未ログイン       | `/login` へ redirect                                      |
| buyer            | `/buyer` へ redirect                                      |
| admin            | `/admin` へ redirect                                      |
| 問い合わせ取得   | Server 側で `breeder_id = ログイン breeder.id` を明示     |
| クライアント入力 | `breeder_id` / `user_id` は受け取らない                   |

---

## 4. 問い合わせ取得条件

```
inquiries.breeder_id = ログイン breeder.id
AND inquiries.deleted_at IS NULL
```

- status による一覧除外なし（`open`〜`closed` すべて対象）
- 並び順: `last_message_at DESC NULLS LAST` → `created_at DESC`
- 取得上限: `INQUIRY_LIST_MAX_ITEMS`（50 件）

---

## 5. 一覧表示（BR-12 一覧）

| 表示項目           | 取得方法                                                           |
| ------------------ | ------------------------------------------------------------------ |
| 犬猫名             | `listPetDisplayNamesForBreeder()` — ブリーダー所有 `pets` テーブル |
| 購入希望者表示名   | `get_inquiry_buyer_display_name` RPC                               |
| 問い合わせ状態     | `getInquiryStatusLabel()`（BY-05/BY-06 共通）                      |
| 最終メッセージ日時 | `last_message_at` または `created_at`                              |
| 未読 Badge         | buyer 送信かつ `is_read = false` の件数                            |
| 詳細を見る         | `/breeder/inquiries/[inquiryId]`                                   |

### 空状態

- 見出し: 問い合わせはまだありません。
- 説明: 購入希望者からの問い合わせが届くと、ここに表示されます。

---

## 6. 詳細・返信（BR-12 詳細）

### サマリー表示

| 表示項目           | 備考                                |
| ------------------ | ----------------------------------- |
| 犬猫名・種別等     | `loadInquiryPetSummaryForBreeder()` |
| 購入希望者表示名   | RPC の `display_name` のみ          |
| 問い合わせ状態     | 日本語ラベル                        |
| 問い合わせ開始日時 | `created_at`                        |

### 表示しない buyer 情報（Decision No.112）

- メールアドレス
- 電話番号
- 住所
- `full_name`

`buyers` テーブルへの breeder SELECT RLS は追加していない。

---

## 7. 購入希望者表示名取得（RPC）

| 項目           | 内容                                                                  |
| -------------- | --------------------------------------------------------------------- |
| 関数           | `public.get_inquiry_buyer_display_name(p_inquiry_id uuid)`            |
| Migration      | `20260821153000_create_get_inquiry_buyer_display_name_rpc.sql`        |
| 呼び出し       | `getInquiryBuyerDisplayName()` / `getInquiryBuyerDisplayNamesByIds()` |
| Service Role   | **禁止**（通常 Supabase server client のみ）                          |
| フォールバック | RPC 結果が NULL の場合「購入希望者」                                  |

**重要:** Migration が DB 未適用の場合、表示名はフォールバック表示になる。実機確認前に migration 適用が必要。

---

## 8. メッセージ履歴

- BY-06 と同型の `InquiryMessageList` を再利用
- 時系列昇順（`created_at ASC`）
- buyer / breeder を視覚的に区別（`isOwnMessage: sender_type === "breeder"`）

---

## 9. 返信処理

| 項目                 | 仕様                                          |
| -------------------- | --------------------------------------------- |
| 入力上限             | 2000 文字（`INQUIRY_MESSAGE_MAX_LENGTH`）     |
| ボタン               | 「返信する」                                  |
| 二重送信防止         | `disabled` + 「送信中…」                      |
| 送信不可 status      | `closed` / `completed`（BY-06 と同様）        |
| INSERT               | `sender_type = 'breeder'`                     |
| `last_message_at`    | 更新                                          |
| 初回 breeder 返信    | `status = 'open'` のとき `replied` に更新     |
| 既読化（詳細表示時） | buyer 送信分の未読を既読化（Decision No.116） |

Server Action: `sendBreederInquiryMessageAction()`

---

## 10. 未読・既読

| 画面 | 未読対象                         | 既読化                          |
| ---- | -------------------------------- | ------------------------------- |
| 一覧 | buyer 送信かつ `is_read = false` | **行わない**                    |
| 詳細 | 同上を Badge 表示                | 詳細表示時に buyer 未読を既読化 |

breeder 自身が送った未読（`sender_type = 'breeder'`）は未読 Badge に含めない。

---

## 11. 犬猫情報取得

| ケース             | 方法                                                                            |
| ------------------ | ------------------------------------------------------------------------------- |
| ブリーダー所有 pet | `pets` テーブル直接（`public_display_name` → `management_name` フォールバック） |
| pet 取得不可       | `inquiries.subject` から名称復元（Decision No.115 準拠）                        |

公開 pet View のみに限定しない。RLS 変更なし。

---

## 12. N+1 対策（一覧）

固定クエリ構成:

1. `inquiries` 一覧（breeder_id フィルタ）
2. 未読件数一括（buyer 未読）
3. 犬猫名一括（`pets` テーブル）
4. 購入希望者表示名（RPC を inquiry 件数分 `Promise.all` — 最大 50 件）

inquiry 件数ごとの個別 SELECT は行わない（RPC 呼び出しは件数分）。

## 19. 残課題

- **RPC migration 適用** — `20260821153000` を Supabase 実 DB に適用しないと購入希望者表示名がフォールバックになる
- **実機 E2E 確認** — ブリーダーログイン → 一覧 → 詳細 → 返信 → buyer 側 BY-06 で受信確認
- **BR-06 ダッシュボード** — KPI・最近の問い合わせは引き続きモック（第1期スコープ外）
