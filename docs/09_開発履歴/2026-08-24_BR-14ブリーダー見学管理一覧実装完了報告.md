# BR-14 ブリーダー見学管理一覧 実装完了報告

## 実装内容

- URL: `/breeder/visits`（BR-14 設計どおり）
- `listVisitsForBreeder()` — RLS SELECT、`breeder_id` + `deleted_at IS NULL`
- `loadBreederVisitsPageData()` — 認証・バッチ取得・ソート・表示 DTO 組み立て
- `BreederVisitListView` / `BreederVisitListCard` — カード一覧 UI
- 各カードから `getBreederVisitDetailPath()` → BR-15 URL へリンク（BR-15 本体は次工程）

## DB変更

変更なし（migration なし、RLS 変更なし、新規 RPC なし）

## データ取得方法

1. `requireBreeder()` → `getBreederIdByUserId`
2. `visits` SELECT（`breeder_id` 一致、`deleted_at IS NULL`）
3. `listInquiriesByIdsForBreeder` — 問い合わせ status
4. `listPetCardSummariesForBreeder` — 犬猫名・種別・写真（非公開 pet も breeder 本人 READ）
5. `getInquiryBuyerDisplayNamesByIds` — RPC `get_inquiry_buyer_display_name`

## 並び順

BR-14 設計に従い、アプリ側 `sortBreederVisitsForList()` でソート:

1. `status = requested` 優先
2. `scheduled_at ASC NULLS LAST`
3. `requested_at DESC`
4. `created_at DESC`

## ステータス表示

| status      | ブリーダー向けラベル |
| ----------- | -------------------- |
| `requested` | 見学希望（要対応）   |
| `scheduled` | 見学予定             |
| `completed` | 見学完了             |
| `canceled`  | キャンセル           |

日時ラベル: 見学希望日時 / 確定日時 / 完了日時 / キャンセル日時（status に応じて `formatVisitListPrimaryDateTime` を共用）

## 個人情報表示範囲

- 表示: 購入希望者 `display_name` のみ（RPC、未設定時は「購入希望者」fallback）
- 非表示: メール・電話・住所・生年月日等（BR-14 / Decision No.112 準拠）

## セキュリティ確認

- Service Role 不使用
- RLS 維持（既存 SELECT ポリシーのみ）
- `requireBreeder()` — 未ログイン → login、buyer → `/buyer`、admin → `/admin`
- inquiry / visit は `breeder_id` で二重フィルタ
- buyer 表示名は RPC のみ（`buyers` テーブル直接 SELECT なし）
