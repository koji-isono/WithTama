## DB変更

変更なし（migration なし、schema 変更なし、RLS 変更なし）

## データ取得方法

1. `requireBuyer()` → `buyers.id`
2. `visits` SELECT（`buyer_id` 一致、`deleted_at IS NULL`）— **新規 RPC なし**
3. `listInquiriesByIdsForBuyer` — 関連 inquiry（buyer 本人のみ）
4. `listPublishedPetsForPublicByIds` + subject フォールバック — 非公開 pet も既存 visit は表示（Decision No.115 整合）
5. `listBreederPublicNamesByIds` — ブリーダー表示名

Service Role 不使用。`buyer_id` は auth 解決値のみ使用。

## 並び順

[[docs/04_画面設計/BY-08_見学予定一覧]] の定義を採用:

1. `scheduled_at DESC NULLS LAST`
2. `requested_at DESC`
3. `created_at DESC`

## ステータス表示

BY-09 と同一の `VISIT_STATUS_LABELS` / `getVisitStatusLabel` を再利用。

| status    | ラベル       | 日時表示                |
| --------- | ------------ | ----------------------- |
| requested | 見学希望受付 | 第一希望 `requested_at` |
| scheduled | 見学日時確定 | `scheduled_at`（強調）  |
| completed | 見学完了     | `completed_at`          |
| canceled  | キャンセル   | `canceled_at`           |

## セキュリティ確認

- Service Role 不使用
- RLS 変更なし
- buyer 本人の visit のみ SELECT（repository + RLS）
- `deleted_at IS NULL` フィルタ
- 他 buyer / admin / breeder の visit は RLS で非表示（E2E 確認）
