## 1. 結論

**フル統合テストは未実施（停止）。**

`.env.local` に **`SEC_TEST_BUYER_EMAIL` / `SEC_TEST_BUYER_PASSWORD` が未設定** のため、`scripts/test-visit-rpcs.mts` は起動直後にエラー終了する。購入希望者（buyer）JWT が必須の RPC フロー（`request_visit` 成功〜`cancel_visit` 当事者テスト）を **推測 credentials なしでは実行できない**。

**実施できた範囲:**

- 本番 DB に 4 RPC が存在すること（anon 呼び出し → `permission denied for function`）
- ブリーダーテストアカウントでのサインイン成功
- ブリーダーによる `request_visit`（ダミー inquiry）→ `unauthorized` 拒否

**`npm run test:visit-rpcs`:** 起動失敗（`Missing environment variable: SEC_TEST_BUYER_EMAIL`）

## 4. 不足環境変数と候補

### 4.1 不足

| 変数                      | 影響                                            |
| ------------------------- | ----------------------------------------------- |
| `SEC_TEST_BUYER_EMAIL`    | buyer サインイン不可 → 統合テスト本体が実行不可 |
| `SEC_TEST_BUYER_PASSWORD` | 同上                                            |

### 4.2 利用可能な既存アカウント

| 種別       | 環境変数                          | 用途（今回）           |
| ---------- | --------------------------------- | ---------------------- |
| ブリーダー | `SEC_TEST_BREEDER_EMAIL/PASSWORD` | 部分拒否テストのみ実施 |
| 管理者     | `SEC_TEST_ADMIN_EMAIL/PASSWORD`   | 未使用                 |

### 4.3 購入希望者テストアカウント候補

- **Supabase Authentication** 上に、**buyer ロール**（`buyers` 行が `auth.users` と紐づく）のテストユーザーを 1 件用意する必要がある。
- 既存ドキュメント（[問い合わせ送信者表示修正報告](./2026-08-24_問い合わせ送信者表示修正とE2E確認完了報告.md)）でも `SEC_TEST_BUYER_*` 未設定が記録されている。
- **本番 Auth 上の具体的メールアドレスは、`.env.local` 未設定のため特定せず**（推測で `.env.local` へ書き込まない）。

**推奨:** `/signup` で buyer 登録済みテストユーザーを 1 件決め、`.env.local` に `SEC_TEST_BUYER_EMAIL` / `SEC_TEST_BUYER_PASSWORD` を追加後、`npm run test:visit-rpcs` を再実行。
