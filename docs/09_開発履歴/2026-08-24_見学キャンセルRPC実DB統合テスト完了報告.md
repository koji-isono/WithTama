## 1. 目的

`cancel_visit` の実 DB 統合テストが **SKIP なく必ず実行される** ように `scripts/test-visit-rpcs.mts` を拡張し、以下を本番 DB 上で検証する。

2. ブリーダーによる見学日時確定（`schedule_visit`）

5. `cancellation_reason` が正しく保存されること
6. 権限外ユーザー（admin）からのキャンセル拒否
7. 既存の happy path 12 テストを維持すること

Decision No.117〜123・`visits.md`・画面設計（BY-09 / BR-15）の仕様（`canceled` 綴り、`inquiries.status → replied`）との整合性を維持する。

## 3. テスト設計（本番データ保護）

### 3.1 方針

| 方針 | 内容 |
| ---- | ---- |
| テスト専用データ | タイムスタンプ付き PREFIX `[VISIT-RPC <epoch>]` で subject / message / cancellation_reason を識別 |
| inquiry 作成 | 既存 inquiry が使えない場合、`published_pets_public` 経由で公開 pet を解決し buyer RLS で **新規 inquiry + 初回 message** を INSERT |
| cancel 専用 inquiry | happy path とは **別 inquiry を毎回新規作成**（1 inquiry = 1 visit 制約のため） |
| 既存データ | 既存 inquiry / visit を UPDATE・DELETE しない。新規行のみ追加 |
| Service Role | 不使用（JWT + `.rpc()` のみ） |

### 3.2 使用環境変数

| 変数 | 必須 | 用途 |
| ---- | ---- | ---- |
| `NEXT_PUBLIC_SUPABASE_URL` | ✅ | Supabase 接続 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | ✅ | anon / authenticated クライアント |
| `SEC_TEST_BUYER_EMAIL` / `PASSWORD` | ✅ | buyer JWT |
| `SEC_TEST_BREEDER_EMAIL` / `PASSWORD` | ✅ | breeder JWT |
| `SEC_TEST_INQUIRY_PET_ID` | 任意 | 公開 pet の明示指定（未設定時は `published_pets_public` で自動解決） |
| `SEC_TEST_ADMIN_EMAIL` / `PASSWORD` | 推奨 | admin による `cancel_visit` 拒否テスト |
