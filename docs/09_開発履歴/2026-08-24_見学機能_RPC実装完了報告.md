## 3. RPC ごとの引数・戻り値

### 3.1 `request_visit`

| 項目       | 内容                                                                                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **引数**   | `p_inquiry_id uuid`, `p_requested_at timestamptz`, `p_requested_at_second timestamptz DEFAULT NULL`, `p_requested_at_third timestamptz DEFAULT NULL`, `p_message text DEFAULT NULL` |
| **戻り値** | `uuid`（新規 `visits.id`）                                                                                                                                                          |
| **実行者** | buyer のみ                                                                                                                                                                          |

**処理（1 トランザクション）:**

1. inquiry 存在・`deleted_at IS NULL`・本人 buyer・`status IN ('open','replied')`
2. 同一 inquiry の visit 未存在（UNIQUE 整合）
3. 第一希望必須・未来日時。第二・第三は任意（第三は第二必須、昇順）
4. breeder / pet 関連性検証
5. `visits` INSERT（`status=requested`, `result=pending`）
6. `inquiries.status = 'visit_requested'`
7. `p_message` 非空時 `inquiry_messages` INSERT + `last_message_at` 更新

### 3.2 `schedule_visit`

| 項目       | 内容                                            |
| ---------- | ----------------------------------------------- |
| **引数**   | `p_visit_id uuid`, `p_scheduled_at timestamptz` |
| **戻り値** | `void`                                          |
| **実行者** | breeder のみ                                    |

**処理:**

- 本人 breeder の visit、`deleted_at IS NULL`、`status = 'requested'`
- inquiry `visit_requested`、visit / inquiry 関連性一致
- **`p_scheduled_at` は未来日時必須**（`p_scheduled_at <= now()` は `scheduled datetime must be in the future` で拒否）
- `scheduled_at` 設定、`status = scheduled`、`confirmed_by_breeder_at = now()`
- `inquiries.status = 'visit_scheduled'`

### 3.3 `complete_visit`

| 項目       | 内容                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------- |
| **引数**   | `p_visit_id uuid`, `p_animal_confirmed boolean`, `p_explanation_completed boolean`, `p_result text` |
| **戻り値** | `void`                                                                                              |
| **実行者** | breeder のみ                                                                                        |

**処理:**

- 本人 breeder、`status = scheduled`、inquiry `visit_scheduled`
- **`p_animal_confirmed IS TRUE` かつ `p_explanation_completed IS TRUE` 必須**（NULL / FALSE は `implementation flags must be true` で拒否）
- `p_result IN ('contracted','declined','considering')`（`pending` 不可）
- 実施フラグ・`result`・`completed_at`・`status = completed`
- `inquiries.status = completed`

### 3.4 `cancel_visit`

| 項目       | 内容                                                         |
| ---------- | ------------------------------------------------------------ |
| **引数**   | `p_visit_id uuid`, `p_cancellation_reason text DEFAULT NULL` |
| **戻り値** | `void`                                                       |
| **実行者** | buyer **または** breeder（当事者のみ）                       |

**処理:**

- `status IN ('requested','scheduled')`
- buyer / breeder いずれかが `auth.uid()` で当事者確認
- inquiry status が visit 状態と整合（requested↔visit_requested、scheduled↔visit_scheduled）
- `status = canceled`、`canceled_at = now()`、理由保存（任意・2000 文字上限）
- `inquiries.status = 'replied'`（メッセージ継続可）

## 4. 認可方式

| RPC                                 | 認可                                                                              |
| ----------------------------------- | --------------------------------------------------------------------------------- |
| `request_visit`                     | `buyers.user_id = auth.uid()` かつ `inquiry.buyer_id` 一致。`is_admin()` **拒否** |
| `schedule_visit` / `complete_visit` | `breeders.user_id = auth.uid()` かつ `visit.breeder_id` 一致。admin **拒否**      |
| `cancel_visit`                      | buyer **または** breeder が visit 当事者。admin **拒否**                          |

共通:

- `auth.uid() IS NULL` → `authentication required`
- `SET search_path = ''` + `public.*` 完全修飾
- `SECURITY DEFINER`（RLS バイパスは関数所有者。テーブル操作は RPC 内バリデーションで制限）
- `REVOKE ALL … FROM PUBLIC` / `FROM anon`
- `GRANT EXECUTE … TO authenticated` のみ

## 5. status 遷移

### visits.status

```
requested --schedule_visit--> scheduled --complete_visit--> completed
    |                            |
    +-------- cancel_visit -----+--------> canceled
```

### inquiries.status（RPC 連動）

| RPC              | inquiries.status    |
| ---------------- | ------------------- |
| `request_visit`  | → `visit_requested` |
| `schedule_visit` | → `visit_scheduled` |
| `complete_visit` | → `completed`       |
| `cancel_visit`   | → `replied`         |

## 7. セキュリティ対策（静的レビュー）

| 観点                    | 対策                                                                                             | 結果 |
| ----------------------- | ------------------------------------------------------------------------------------------------ | ---- |
| 権限昇格                | 各 RPC で `auth.uid()` 必須。admin は mutation RPC から明示拒否。buyer/breeder ID は DB から解決 | ✅   |
| IDOR                    | visit / inquiry を `FOR UPDATE` 取得後、`buyer_id` / `breeder_id` と `auth.uid()` を照合         | ✅   |
| SECURITY DEFINER 危険性 | `search_path = ''`。未修飾識別子なし。操作列を RPC 内固定                                        | ✅   |
| EXECUTE 権限            | PUBLIC / anon REVOKE、authenticated のみ GRANT                                                   | ✅   |
| 不正 status 遷移        | UPDATE … WHERE に旧 status 条件 + inquiry status 整合チェック                                    | ✅   |
| 他人 visit 更新         | 当事者 ID 不一致で `unauthorized`                                                                | ✅   |
| 論理削除                | `visits` / `inquiries` / buyers / breeders で `deleted_at IS NULL` 確認                          | ✅   |
| 部分更新不整合          | 関数全体が単一トランザクション。失敗時ロールバック                                               | ✅   |
| 1 inquiry 1 visit       | INSERT 前 EXISTS + DB UNIQUE(`inquiry_id`)                                                       | ✅   |
| 関連性                  | visit と inquiry の buyer/breeder/pet_id 一致を検証                                              | ✅   |
| buyer/breeder 分離      | request=cancel(buyer側)/schedule+complete=breeder。更新列は RPC ごとに固定（No.123）             | ✅   |
| Service Role            | アプリ・テストとも未使用                                                                         | ✅   |
| 入力バリデーション      | `schedule_visit`: 未来日時のみ。`complete_visit`: 実施フラグ両方 TRUE 必須                       | ✅   |

**本番適用前の推奨:** staging で `scripts/test-visit-rpcs.mts` を migration 適用後に実行。
