## 新規 RPC

| RPC                              | 責務                                               |
| -------------------------------- | -------------------------------------------------- |
| `submit_breeder_application()`   | 初回提出（引数なし、`auth.uid()` で breeder 特定） |
| `resubmit_breeder_application()` | 再提出（同上）                                     |

---

## 初回提出処理

- `completeBreederProfile` — 既存 validation 維持
- DB 更新は `submit_breeder_application` RPC に委譲
- `profile_completed = true`、verification status → `submitted` を RPC 内で原子的に更新

---

## 再提出処理

- `resubmission_required` のみ許可
- `review_status` → `submitted` + `submitted` log
- verification status / `membership_status` / `approved_at` は **変更しない**

---

## status 遷移

```
draft --submit_breeder_application--> submitted
resubmission_required --resubmit_breeder_application--> submitted
```

再提出から `under_review` へは **直接遷移しない**（Decision No.126）。

---

| 操作     | identity / business verification |

| 再提出   | **変更なし**                     |

## membership_status

初回提出・再提出とも **変更しない**。

## submitted log

- action = `submitted`（Decision No.131 準拠）
- 初回・再提出とも同一 action を追記
- schema CHECK 変更なし

## authorization

- `auth.uid()` 必須
- admin からの実行拒否（`invalid submit actor`）
- buyer / 非ログイン → `breeder not found` または `authentication required`
- RPC 引数に `user_id` / `breeder_id` を **受け取らない**
