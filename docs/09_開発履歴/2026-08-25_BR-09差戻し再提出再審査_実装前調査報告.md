# BR-09 差戻し→修正→再提出→再審査 実装前調査報告

## BR-09 目的

管理者が差戻ししたブリーダー申請について、

1. ブリーダーが差戻し理由を確認
2. 申請内容を修正
3. 再提出
4. 管理者が再審査（審査開始 → 承認 / 再差戻し / 却下）

までを第1期スコープで完成させる。**既存 AD-02 管理者操作は変更・破壊しない。**

## 現行業務フロー（正本）

[docs/03_業務フロー/README.md](../03_業務フロー/README.md) §ブリーダー：プロフィール申請〜審査

```
draft
  → BR-09 completeBreederProfile → submitted (+ submitted log)
  → AD-02 審査開始 → under_review
  → 差戻し RPC → resubmission_required (+ returned log, comment 必須)
  → BR-09 再提出 → submitted (+ submitted log 追記)
  → AD-02 審査開始 → under_review
  → 承認 / 再差戻し / 却下
```

**再提出後は `submitted` に戻す。** `under_review` へは管理者の `start_breeder_review` のみ（Decision No.126）。

### 再提出 RPC

**存在しない。** ブリーダー側は `completeBreederProfile()`（Server Action）のみ。

現状 `completeBreederProfile`（`src/features/breeder-profile/service.ts`）:

- `review_status` を無条件で `submitted` に更新
- **`resubmission_required` ガードなし**
- **`breeder_review_logs` への INSERT なし**
- verification を `submitted` に上書き（差戻し後も同値だが、再提出専用処理ではない）

**推奨:** 犬猫審査・管理者審査と同様、**ブリーダー再提出用 RPC**（例: `resubmit_breeder_application`）で `breeders` 更新 + `submitted` log を **原子的**に実行。初回提出の `submitted` log 不足も同 RPC または `completeBreederProfile` 改修で解消。

## テストケース（実装時）

1. 管理者が差戻しできる
2. 差戻し理由必須
3. ブリーダーが差戻し理由を確認できる
4. 他ブリーダーは理由を見られない
5. `resubmission_required` 中は修正可能
6. 再提出できる
7. 再提出後 `review_status = submitted`
8. `breeder_review_logs` に `submitted` が追記される
9. 管理者が再審査開始できる（`resubmission_required` → 再提出 → `start_breeder_review`）
10. 再承認できる
11. 再差戻しできる
12. 却下できる
13. buyer は操作不可
14. 非ログインは操作不可
15. `submitted` / `under_review` / `approved` / `rejected` から再提出不可
16. 書類 Storage 権限維持
17. `membership_status` 意図しない変更なし
18. （追加）初回提出時 `submitted` log が記録される
19. （追加）`submitted` / `under_review` 中のプロフィール編集可否（Decision 後）
