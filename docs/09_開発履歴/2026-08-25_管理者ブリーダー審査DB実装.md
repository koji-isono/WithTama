## 1. 目的

管理者によるブリーダー審査（審査開始・承認・差戻し・却下）を、犬猫審査（AD-10 / AD-11）と同様の SECURITY DEFINER RPC + 監査ログパターンで DB 層に実装する。

- 審査履歴テーブル `breeder_review_logs` の新設
- 管理者向け `breeder-documents` Storage SELECT RLS
- 審査 RPC 4 種の作成
- SEC-TEST 統合テストの追加

**Supabase 本番 DB への migration 適用は未実施。** `supabase db push` 等も実行していない。

## 4. breeder_review_logs

`public.breeder_review_logs` を新設。

| カラム          | 型            | 備考                                                                  |
| --------------- | ------------- | --------------------------------------------------------------------- |
| `id`            | uuid PK       | `gen_random_uuid()`                                                   |
| `breeder_id`    | uuid FK       | `breeders.id`                                                         |
| `action`        | text          | `submitted` / `review_started` / `approved` / `returned` / `rejected` |
| `comment`       | text nullable | `returned` / `rejected` 時必須                                        |
| `actor_user_id` | uuid FK       | `auth.users.id`                                                       |
| `created_at`    | timestamptz   | `now()`                                                               |

**RLS:**

- breeder 本人: 自分の `breeder_id` のログ SELECT、`action = submitted` の INSERT のみ
- admin: 全ログ SELECT、審査 action の INSERT
- UPDATE / DELETE ポリシーなし（追記専用）

---

## 5. Storage RLS

`storage.objects` に `breeder_documents_storage_select_admin` を追加。

- `bucket_id = 'breeder-documents'`
- `public.is_admin() = true`
- **SELECT のみ**（INSERT / UPDATE / DELETE は追加しない）
- 既存のブリーダー本人向けポリシーは変更なし

---

## 6. RPC 4 種

| RPC                                              | 遷移                                                   | ログ action      | 備考                                                                                                                                                    |
| ------------------------------------------------ | ------------------------------------------------------ | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `start_breeder_review(p_breeder_id)`             | `submitted` / `resubmission_required` → `under_review` | `review_started` | admin のみ                                                                                                                                              |
| `approve_breeder_review(p_breeder_id)`           | `under_review` → `approved`                            | `approved`       | 書類 path・Storage 実体・`registration_expires_at >= CURRENT_DATE` 必須。verification 両方 `verified`、`approved_at` 設定。**`membership_status` 不変** |
| `return_breeder_review(p_breeder_id, p_comment)` | `under_review` → `resubmission_required`               | `returned`       | comment 必須。verification 不変                                                                                                                         |
| `reject_breeder_review(p_breeder_id, p_comment)` | `under_review` → `rejected`                            | `rejected`       | comment 必須。verification 不変（Decision No.128）                                                                                                      |

共通セキュリティ（AD-11 パターン準拠）:

- `SECURITY DEFINER` + `SET search_path = public`
- `auth.uid()` / `public.is_admin()` 確認
- `REVOKE EXECUTE FROM PUBLIC` / `anon`、`GRANT EXECUTE TO authenticated`
- breeders UPDATE + log INSERT を同一 RPC 内で原子的に実行

---

## 7. status 遷移（今回 RPC で許可）

```
submitted ──start──► under_review
resubmission_required ──start──► under_review
under_review ──approve──► approved
under_review ──return──► resubmission_required
under_review ──reject──► rejected
```

上記以外は `invalid review status` で拒否。新 status は追加していない。

---

## 8. セキュリティ

- Service Role Key は使用しない
- 管理者以外は全 RPC 拒否（`admin required`）
- 監査ログは必要最小限の閲覧権限（breeder 本人 + admin）
- Storage は admin に SELECT のみ付与

## 9. テスト内容

| スクリプト                                    | 用途                                         |
| --------------------------------------------- | -------------------------------------------- |
| `scripts/prepare-sec-test-breeder-review.mts` | SEC-TEST ブリーダーを `submitted` にリセット |

`package.json` スクリプト:

- `npm run prepare:sec-test-breeder-review`

テスト項目（最低限 22 件）:

1. 非 admin → start 拒否
2. submitted → under_review 成功
3. review_started log
4. submitted のまま approve 拒否
5. under_review → approve 成功
6. verification 両方 verified
7. approved_at 設定
8. membership_status 不変
9. 登録期限切れ → approve 拒否
10. registration_expires_at NULL → approve 拒否
11. identity_document_path なし → approve 拒否
12. business_license_path なし → approve 拒否
13. return comment なし → 拒否
14. return 空白のみ → 拒否
15. under_review → resubmission_required 成功
16. returned log + comment
17. reject comment なし → 拒否
18. under_review → rejected 成功
19. rejected log + comment
20. buyer / breeder 本人 → admin RPC 拒否
21. admin が breeder-documents SELECT 可能
22. buyer が他人の breeder-documents SELECT 不可

**Migration 未適用時:** RPC 存在チェックで FAIL し、適用後に再実行が必要。

## 11. BR-09 残作業（`submitted` ログ）

今回の migration では **`submitted` ログの自動生成 Trigger は設けていない**（設計書どおり）。

### 初回提出

BR-09 の `completeBreederProfile`（または同等 RPC）成功時に、同一トランザクションで:

1. `breeders.review_status = 'submitted'`
2. `breeder_review_logs` に `action = 'submitted'` を INSERT（`actor_user_id = auth.uid()`）

### 再提出

差戻し後（`resubmission_required`）の再提出成功時も同様に **`submitted` を追記**する。

- 申請日時（AD-01 / AD-02 表示）は `action = 'submitted'` の **最新行** の `created_at` を使用
- 初回・再提出の区別はログ行数 / 時系列で判別可能

**次工程:** BR-09 再提出処理 + `completeBreederProfile` への `submitted` ログ INSERT 実装。
