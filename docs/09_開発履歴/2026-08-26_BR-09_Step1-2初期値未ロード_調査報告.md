# BR-09 Step 1 / 2 初期値未ロード 調査報告

## 調査背景

実ブラウザ E2E 確認中、管理者差戻し後に BR-09 プロフィール編集（Step 1 基本情報）へ遷移したところ、以前保存・提出済みの屋号・代表者氏名などが空欄に見える事象を報告。

**本調査は原因特定のみ。** 修正・commit・push・DB 変更は実施していない。

---

## 報告サマリー

| 項目                       | 結果                                             |
| -------------------------- | ------------------------------------------------ |
| 現象                       | 確認 / コード上は常に再現                        |
| DB 保存データ              | **残っている**                                   |
| BR-09 loader               | **問題あり**（Step 1 / 2 未実装）                |
| Step 1 へのデータ受渡し    | **問題あり**                                     |
| form 初期値                | **問題あり**（Step 1 / 2）                       |
| Step 2〜5                  | Step 1 / 2 のみ同様の問題。Step 3 / 4 は正常想定 |
| 差戻し処理によるデータ変更 | **なし**                                         |
| 原因                       | Step 1 / 2 の DB 読込・フォーム初期化が未実装    |
| データ消失                 | **なし**（表示されていないだけ）                 |

---

## 現象

管理者から差戻し → ブリーダーダッシュボードで差戻し理由表示（正常）→「申請内容を修正する」→ BR-09 Step 1 へ遷移 → **屋号・代表者氏名などが空欄**。

期待動作：前回保存済み内容をフォームに表示 → 必要箇所のみ修正 → 保存 → 再提出。

---

## DB 保存データ

**結論: 残っている（消えていない）**

SEC_TEST ブリーダー（`c975c260-d0b8-40f4-9745-1557c64eb856`）を breeder JWT で read-only 確認。

| カラム                  | 値（抜粋）           |
| ----------------------- | -------------------- |
| `business_name`         | `テスト２`           |
| `representative_name`   | `だいひょうしゃ２`   |
| `phone`                 | `0123456780`         |
| `postal_code`           | `860-0002`           |
| `prefecture`            | `宮城県`             |
| `city` / `address_line` | 保存済み             |
| `breeding_policy`       | 長文 + `[BR-09-E2E]` |
| `profile_completed`     | `true`               |

**補足:** ブラウザ報告の「テスト屋号」と DB 上の `business_name`（`テスト２`）に表記差の可能性あり。admin 検索（`%テスト%`）では上記 1 件のみ。いずれにせよプロフィール列は DB に存在。

## BR-09-1 編集ガードとの関係

**無関係。**

`loadBreederProfilePageContext` / `isProfileEditable` は layout ガードと差戻し表示のみ。Step 1 / 2 のフォーム初期値取得には触れていない。

`draft` と `resubmission_required` で loader / 初期化処理に差はない。

---

## 原因

**Step 1 / Step 2 が BR-09 初版から DB 読込・フォーム初期化が未実装のまま。** BR-09-1〜3 でも loader / 初期値連携は追加されていない。

- **「表示されていないだけ」** — DB データ消失ではない
- **差戻しフロー固有ではない** — 初回 `draft` 編集時も同症状
- **BR-09-1 編集ガードが原因ではない**

## 推奨修正

Step 3 / 4 と同パターンで実装（**DB / Migration / RPC / RLS 変更不要**）:

1. `repository` に `getBasicProfileByUserId` / `getLocationProfileByUserId` を追加
2. `loaders.ts` に `loadBasicProfile` / `loadLocationProfile` を追加
3. `basic/page.tsx` / `location/page.tsx` を async SC + loader + `initialInput` props に変更
4. `BasicInfoStepForm` / `LocationStepForm` に `initialInput` props を追加し `useState(initialInput)` に

`review_status` による loader 分岐は不要（editable ガードは既存 layout / Action で維持）。
