# BR-09 実ブラウザ E2E DB 乖離 調査報告

## 調査目的

実ブラウザ E2E では承認まで PASS したが、報告書作成時の DB READ ONLY 確認では SEC_TEST breeder（`c975c260-…`）が `submitted` / `approved_at null` となり、実ブラウザ結果と乖離があった。原因を READ ONLY で特定する。

**本調査は SELECT のみ。** UPDATE / INSERT / DELETE / RPC 実行 / 自動テスト実行 / コード修正 / commit / push は実施していない。

---

## 結論

| 項目       | 結果                                                               |
| ---------- | ------------------------------------------------------------------ |
| 原因分類   | **B** — 実ブラウザと DB 確認で **異なる breeder_id** を参照        |
| 実ブラウザ | `bed9a709-…`（`user_id` `92707560-…`）— **承認済み・審査ログ一致** |
| DB 報告時  | `c975c260-…`（`user_id` `92bc1954-…` / SEC_TEST）— **submitted**   |
| 主因       | breeder_id / user_id の取り違え（同一 DB 内の別レコード）          |

A（自動テストによる SEC_TEST の reset）も `c975c260` には該当するが、**実ブラウザ E2E 乖離の主因は B**。

### breeder 同一性判定について

実ブラウザ E2E 中にユーザー本人が **事業所名（`business_name`）を手動変更**している。`business_name` はユーザーが変更可能なため、**breeder 同一性判定には使用しない**。

同一性の正本: `breeder_id` / `user_id` / `breeder_review_logs`（時刻・action・comment）/ `approved_at` 等の一意な識別情報。
