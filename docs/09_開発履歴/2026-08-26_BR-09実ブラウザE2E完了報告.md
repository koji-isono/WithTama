# BR-09 実ブラウザ E2E 完了報告

## 1. 概要

BR-09「差戻し → 修正 → 再提出 → 再審査 → 承認」の一連フローを、実ブラウザ（localhost + Supabase 接続環境）で確認した。

## 19a. DB 乖離の経緯（解消済み）

報告書初版作成時、DB READ ONLY 確認で **SEC_TEST breeder**（`c975c260-d0b8-40f4-9745-1557c64eb856` / `user_id` `92bc1954-…`）を誤って参照していた。

| 項目                     | 誤参照（SEC_TEST）  | 実ブラウザ対象（正）     |
| ------------------------ | ------------------- | ------------------------ |
| breeder_id               | `c975c260-…`        | `bed9a709-…`             |
| user_id                  | `92bc1954-…`        | `92707560-…`             |
| 2026-08-26 承認          | なし（`submitted`） | あり（13:55 `approved`） |
| 13:41 submitted          | なし                | あり                     |
| `E2E実画面確認` returned | なし                | 11:57 あり               |

**原因分類 B** — 実ブラウザと DB 確認で **異なる breeder_id** を参照。UI 承認処理の不具合ではない。

`business_name` は E2E 中の手動変更があり、同一性判定には使用しない。

SEC_TEST breeder については、`test-breeder-profile-resubmit-e2e` / `test-breeder-application-submit-rpcs` / `prepare-sec-test-*` 等が状態を reset する設計である（副次要因 A）。

詳細: [[docs/09_開発履歴/2026-08-26_BR-09実ブラウザE2E_DB乖離調査報告]]
