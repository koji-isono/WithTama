## 差戻し理由取得方法

### 正本

- **BR-06:** バナー + 最新 returned comment（実装済み）
- **BR-09:** ウィザードシェル or Step 5 に **最小表示**（Decision No.135）

### 再利用

BR-06 `getLatestReturnedComment()`（`src/features/breeder-dashboard/repository.ts`）と同一クエリ:

```typescript
.from("breeder_review_logs")
.select("comment")
.eq("action", "returned")
.order("created_at", { ascending: false })
.limit(1)
```

**推奨:** 共通関数を `src/features/breeder-profile/repository.ts` または小さな shared モジュールへ移し、BR-06 / BR-09 双方から import（重複回避）。

表示条件: `review_status === "resubmission_required"` のみ。BR-06 と同フォールバック（comment 未取得時は管理者問い合わせ案内）。

## 保存と再提出の関係

**現行フロー（維持推奨）:**

```
各 Step「保存して次へ」→ DB 永続化
  ↓
Step 5 で書類確認
  ↓
「提出」or「再提出」→ RPC（DB 上の最新データを使用）
```

- 再提出ボタンは **未保存フォームを保存しない**（Step 5 に入力フィールドは書類のみ。Step 1〜4 は各 save Action で永続化済み）
- 再提出前に `validateProfileCompletion(profile)` を UI / Action で実行（初回提出と同様）
- **注意:** `resubmit_breeder_application` RPC は **書類・profile_completed を再検証しない**（status のみ）。UI 側で必須チェックを行う
