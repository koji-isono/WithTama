## 背景

ブリーダー新規登録 E2E 中、確認メール内リンクをクリックすると `localhost:3000/reset-password?error=invalid_link` へ遷移し、「パスワード再設定」「確認中...」のまま正常な会員登録確認フローに戻らない。

| ステップ                                                                   | 結果                                                      |
| -------------------------------------------------------------------------- | --------------------------------------------------------- |
| `/signup` → ブリーダー選択 → メール・パスワード入力 → 「無料会員登録する」 | 正常（確認メール送信メッセージ表示）                      |
| 確認メール内リンクをクリック                                               | **`/reset-password?error=invalid_link` へ遷移（不具合）** |

**本来の期待:**

```
signup 確認メール
  ↓
メール確認
  ↓
Supabase email_confirmed_at 確定
  ↓
WithTama の適切な登録後画面またはログイン画面
```

## 3. `/reset-password` へ飛ぶ原因

**WithTama コードが signup 確認を Recovery 扱いしている**のが主因。

### 3.1 `type` 未指定の `code` を Recovery とみなす

`src/app/(public)/page.tsx`:

```typescript
if (code) {
  const next = type === "recovery" || !type ? "/reset-password" : "/login";
  // ...
  return `/auth/callback?${query.toString()}`;
}
```

`src/components/auth/recovery-link-handler.tsx`:

```typescript
if (code) {
  const next = type === "recovery" || !type ? "/reset-password" : "/login";
  window.location.replace(
    `/auth/callback?next=${encodeURIComponent(next)}&code=${encodeURIComponent(code)}`,
  );
}
```

signup 確認が Site URL（`/?code=...`、`type` なし）に着地すると **`next=/reset-password`** で callback へ送られる。

### 3.2 callback 失敗 → `invalid_link`

`src/app/auth/callback/route.ts`:

```typescript
if (error) {
  if (next === "/reset-password") {
    return NextResponse.redirect(`${origin}/reset-password?error=invalid_link`);
  }
  return NextResponse.redirect(`${origin}/login?error=auth_callback_error`);
}
```

`exchangeCodeForSession` 失敗時（メール別ブラウザでの PKCE 不一致、期限切れ等）、**signup でも** `reset-password?error=invalid_link` へ飛ぶ。

### 3.3 `/auth/confirm` の欠落パラメータも reset-password へ

`src/app/auth/confirm/route.ts`:

```typescript
if (!tokenHash || !type) {
  return NextResponse.redirect(`${origin}/reset-password?error=invalid_link`);
}
```

signup リンクが `token_hash` / `type` 不足で着地すると、**signup/recovery 区別なく** reset-password へ。

### 3.4 二次 UI 問題（「確認中...」のまま）

`reset-password-form.tsx` で `error=invalid_link` 時、useEffect が early return し **`isCheckingSession` が true のまま** → 「パスワード再設定」「確認中...」で止まる（エラー文言ブロックに到達しない）。

## 4. `invalid_link` 生成元

| 生成元                           | 条件                                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------- |
| `src/app/auth/callback/route.ts` | `exchangeCodeForSession` 失敗 **かつ** `next === "/reset-password"`                    |
| `src/app/auth/confirm/route.ts`  | `token_hash` / `type` 欠落、または verifyOtp 失敗（recovery / next=reset-password 時） |
| Supabase / Email Template        | **直接は付与しない**（WithTama server redirect が付与）                                |

repository 全体検索: `invalid_link` は上記 2 route + `reset-password-form.tsx`（表示側）のみ。

## 5. signup / recovery callback 構成

| Route                 | 役割                                   | signup / recovery 区別                                                             |
| --------------------- | -------------------------------------- | ---------------------------------------------------------------------------------- |
| `/auth/callback`      | PKCE `code` → `exchangeCodeForSession` | **`next` パラメータ依存**（signup 用固定値なし）                                   |
| `/auth/confirm`       | `token_hash` + `type` → `verifyOtp`    | `type=recovery` のみ reset-password へ補正。**欠落時は一律 reset-password エラー** |
| `/` (page.tsx)        | query を callback/confirm へ転送       | **`!type` → reset-password**（signup 誤ルーティング）                              |
| `RecoveryLinkHandler` | 同上（Client、root layout）            | 同上                                                                               |
| `/reset-password`     | パスワード変更 UI                      | Recovery 専用。signup 確認の受け皿ではない                                         |

**共用しているが、recovery 優先の分岐になっており signup が誤って reset-password 経路に入る。**

Recovery 専用 redirect ヘルパー（参考）:

```typescript
// src/lib/supabase/auth-redirect.ts
return `${appUrl}/auth/callback?next=/reset-password`;
```

signup 用の同等ヘルパーは **存在しない**。
