## 1. 問題の概要

新規ブリーダー会員登録後、確認メールのリンクをクリックすると `/reset-password?error=invalid_link` へ誤遷移し、パスワード再設定画面で停止していた。

Dashboard 設定とコード修正後も、Confirm signup テンプレートが implicit flow（`/#access_token&...&type=signup`）のままではトップページ hash 着地となり `/login` へ到達できなかった。

---

## 2. 発生していた症状

| 段階                          | 症状                                                                              |
| ----------------------------- | --------------------------------------------------------------------------------- |
| 初期                          | 確認メールクリック → `/reset-password?error=invalid_link`                         |
| コード修正後                  | 誤遷移は解消。ただし `http://localhost:3000/#access_token=...&type=signup` へ着地 |
| 最終（テンプレート B 適用後） | `/auth/confirm` → `/login` へ正常遷移                                             |

Supabase Auth 側のメール確認（Confirmed at）は各段階で成功していた。

---

## 3. 直接原因

1. **`signUp` に `emailRedirectTo` 未指定** → Site URL 着地 + `type` なし `code` が Recovery 扱い
2. **`type === "recovery" \|\| !type` → `/reset-password`**（トップ / RecoveryLinkHandler）
3. **`/auth/callback` 失敗 + `next=/reset-password` → `invalid_link`**
4. **Confirm signup テンプレート `{{ .ConfirmationURL }}`** → implicit flow hash 着地（SSR/PKCE と不整合）

---

## 4. 採用した方式

| レイヤ                 | 方式                                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------- |
| **アプリ（Signup）**   | `emailRedirectTo` → `/auth/callback?next=/login`（補助経路）                             |
| **アプリ（主経路）**   | Dashboard: token_hash → `/auth/confirm?type=signup&next=/login` → `verifyOtp` → `/login` |
| **アプリ（Recovery）** | 既存維持: token_hash → `/auth/confirm?type=recovery` → `/reset-password`                 |
| **共通**               | `auth-callback-next.ts` で next 解決・allowlist・Signup/Recovery 分岐                    |

Signup 確認では **fragment への access_token / refresh_token 露出を標準フローにしない**。

## 6. `/auth/confirm` の役割

| パラメータ                     | 処理                                                                                |
| ------------------------------ | ----------------------------------------------------------------------------------- |
| `token_hash` + `type=signup`   | `verifyOtp` → 成功時 `/login`、失敗時 `/login?error=auth_confirm_error`             |
| `token_hash` + `type=recovery` | `verifyOtp` → 成功時 `/reset-password`、失敗時 `/reset-password?error=invalid_link` |
| パラメータ欠落                 | `/login?error=auth_confirm_error`（reset-password へ誤誘導しない）                  |

サーバー側で token を処理し cookie セッション化。URL fragment への token 露出なし。

---

## 7. Signup と Recovery の分離

| フロー       | 経路                                              | 成功先            | 失敗先                               |
| ------------ | ------------------------------------------------- | ----------------- | ------------------------------------ |
| **Signup**   | confirm/callback + `type=signup` または type 欠落 | `/login`          | `/login?error=auth_*`                |
| **Recovery** | confirm/callback + `type=recovery`                | `/reset-password` | `/reset-password?error=invalid_link` |

Recovery テンプレート・reset-password フォームは今回変更の影響を受けない設計。専用テスト 31 件で分岐を検証済み。

---

## 8. 実ブラウザ E2E 手順

1. WithTama「無料会員登録」→「ブリーダー」選択
2. 未登録メールアドレス + パスワードで「無料会員登録する」
3. 「確認メールを送信しました…」表示を確認
4. Confirm signup メール受信 → 「メールアドレスを確認する」クリック
5. 最終 URL が `/login` であること（hash token なし）を確認
6. 登録メール + パスワードでログイン
7. BR-09 ブリーダープロフィール Step 1「基本情報」へ遷移、未登録状態表示を確認

## 11. メール配送で発見した別問題

E2E 中、新規テスト用ドメイン宛に Resend 経由で **550 RCPT TO … User unknown** が一時発生し、Resend 上 **Bounced → Suppressed** となった。

| 項目                             | 扱い                                      |
| -------------------------------- | ----------------------------------------- |
| WithTama 認証ロジック            | **障害ではない**                          |
| メールアドレス実在               | Roundcube 直接受信可能                    |
| Suppression 解除 + Supabase 再送 | **正常受信**                              |
| DMARC 警告（Resend Insights）    | 550 の直接原因とは **断定しない**（推測） |

**「WithTama 認証 E2E とは別途調査する課題」** として記録。本 commit スコープ外。
