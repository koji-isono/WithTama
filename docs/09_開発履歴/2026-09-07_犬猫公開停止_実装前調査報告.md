## 2. Decision確認

### 2.1 関連 Decision 要約

| No.     | 要点                                                                                                                                | 公開停止との関係                                       |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **93**  | 一覧から汎用 status 変更 UI 禁止。公開申請は専用 Action。**公開停止・掲載終了は別操作**                                             | **本機能の根拠 Decision**                              |
| **94**  | `draft→under_review` のみ専用 RPC。汎用 status API 禁止                                                                             | 停止も同様に **専用 RPC + Server Action** が必要       |
| **99**  | AD-00/10/11 = 犬猫審査。admin 画面採番                                                                                              | 停止は **ブリーダー操作（BR-10）**。審査フローとは独立 |
| **130** | 公開 View 条件 = `review_status=approved` **かつ** `membership_status=active`                                                       | 停止は `pets.status` のみ変更。membership とは独立     |
| **151** | 公開後紹介文改訂は `pending_description` + `description_review_status`。**`pets.status` は published 維持**（改訂審査中も掲載継続） | 停止時に **紹介文改訂状態との整合** が必要（§9）       |

### 2.2 概念の関係整理

```
【初回公開審査】          draft → under_review → published（admin approve）
【公開後紹介文改訂審査】  published 維持 + description_review_status 軸（No.151）
【公開停止】              published → paused（本調査対象・No.93）
【掲載終了】              published → family_decided / closed（pets.md 将来対応）
【再公開】                paused → published（pets.md 記載あり・Decision なし → 未決定）
```

- **公開停止** ≠ **掲載終了**（DB 上は別 status）
- **公開停止** ≠ **紹介文改訂審査**（status 軸と description 軸は分離 — No.151）
- **公開停止** ≠ **membership suspended**（Stripe 課金停止は breeder 単位 — No.144）

## 5. 公開停止方式

### 5.1 方式比較

| 案                        | 内容                                 | 評価                                                   |
| ------------------------- | ------------------------------------ | ------------------------------------------------------ |
| **A. published → paused** | pets.md / CHECK 制約に既存。一時停止 | **推奨**                                               |
| B. published → closed     | 掲載終了。不可逆に近い               | Phase 1 では過剰                                       |
| C. 別フラグ               | 新列追加                             | Migration 増。No.93 の「別操作」は status 遷移で足りる |
| D. deleted_at 論理削除    | Decision No.36 と混同リスク          | 不適                                                   |

### 5.2 推奨案（1つ）

**A. `published → paused` のみを Phase 1 で実装する。**

理由:

- DB CHECK・pets.md stateDiagram・UI ラベルが既に `paused` を定義
- 公開 View は `status = 'published'` 条件のため **View 変更不要**
- `family_decided` / `closed`（掲載終了）は Phase 1 対象外とし、Decision 取得後に別 RPC 化

### 5.3 「一時停止」と「掲載終了」の Phase 1 分離

| 操作                                | Phase 1 | 理由                                        |
| ----------------------------------- | ------- | ------------------------------------------- |
| 一時停止（paused）                  | **IN**  | 成約前の一時非表示。再開余地あり            |
| 掲載終了（family_decided / closed） | **OUT** | 不可逆運用・UI 文言・再公開ポリシーが未決定 |

## 9. 紹介文改訂審査との関係

### 9.1 制約（Migration `20260907100000_*`）

```sql
pets_description_revision_scope_check:
  status = 'published'
  OR (description_review_status = 'none' AND pending_description IS NULL)
```

**`published` 以外へ status 変更する場合、`pending_description` / `description_review_status` をクリアしないと CHECK 違反。**

### 9.2 改訂 RPC の前提

`save/submit/approve/return_pet_description_revision*` はすべて `v_pet.status <> 'published'` で拒否。

### 9.3 推奨整合（実装案・Decision 待ち）

| シナリオ                             | 推奨                                                                                                                                          |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 紹介文審査中（`under_review`）に停止 | **停止 RPC 内で改訂状態をリセット**（`pending_description=NULL`, `description_review_status='none'`）。進行中改訂は **自動取消**（UI で明示） |
| 停止後の pending データ              | 保持しない（CHECK 整合のため）                                                                                                                |
| 再公開時の審査結果                   | 改訂は取消済み。公開中 `description`（旧文）のまま再掲載                                                                                      |

**代替（未決定）:** `description_review_status='under_review'` 中は停止を **拒否** し、先に改訂取下げを要求。

**No.151 を壊さない原則:** 停止中は Public View に出さない（`status≠published`）。改訂審査 AD-10/11 への露出は `description_review_status` で継続するか **停止時にリセットして審査キューから外す** — **明示 Decision なし → 未決定**（推奨: リセットして admin 負荷を下げる）。

## 12. RPC

### 12.1 既存 RPC（参考パターン）

| RPC                       | パターン                                                              |
| ------------------------- | --------------------------------------------------------------------- |
| `submit_pet_for_review`   | SECURITY DEFINER, `search_path`, ownership, status 前提, trigger 通過 |
| `approve_pet_for_publish` | 同上 + `is_admin()`                                                   |

### 12.2 新規 RPC 案

#### `pause_pet_listing(p_pet_id uuid)`

| チェック    | 内容                                             |
| ----------- | ------------------------------------------------ |
| 認証        | `auth.uid() IS NOT NULL`                         |
| 所有        | `pets.breeder_id` = 呼出ユーザーの `breeders.id` |
| 前提 status | `status = 'published'`                           |
| 拒否        | admin / buyer / anon / 他 breeder                |
| 副作用      | `status = 'paused'`。改訂状態リセット（§9 推奨） |
| 二重実行    | `WHERE status = 'published'` で 0 件 → exception |

#### `resume_pet_listing(p_pet_id uuid)`（resume を Phase 1 に含める場合）

| チェック    | 内容                                                |
| ----------- | --------------------------------------------------- |
| 前提 status | `status = 'paused'`                                 |
| 遷移        | `paused → published`（`published_at` は変更しない） |
| 再審査      | **Decision なし — 実装時は product Decision 後**    |

### 12.3 トリガー拡張（Migration 内）

`enforce_pets_status_transition()` に breeder 許可遷移を追加:

```text
published → paused  （breeder 本人、非 admin 分岐）
paused → published  （breeder 本人 — resume 採用時）
```

**SECURITY DEFINER RPC でも trigger は発火**（admin RPC と同様）。trigger 側で許可遷移を定義するのが既存パターンに整合。

## 13. RLS / Security

### 13.1 直接 UPDATE

- breeder は `pets_update_breeder_own` で **status 列も UPDATE 可能**（RLS 上）
- しかし **trigger が `published→paused` を拒否** → 現状ブロック
- テスト: `scripts/test-pets-status-trigger.mts`（直接 PostgREST UPDATE）

### 13.2 RPC セキュリティ checklist

| 項目             | 対応                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| SECURITY DEFINER | 採用（既存 RPC 準拠）                                                                             |
| SET search_path  | `public, pg_temp`                                                                                 |
| GRANT            | `authenticated` のみ。`REVOKE ALL FROM PUBLIC, anon`                                              |
| ownership        | RPC 内 `breeders.user_id = auth.uid()`                                                            |
| admin 拒否       | `NOT is_admin()` または breeder 分岐のみ（admin+breeder は admin ルール優先 — 既存 trigger 準拠） |
| buyer 拒否       | RPC 未 GRANT 以外に breeder チェック                                                              |

**RLS ポリシー変更:** 不要（既存 UPDATE ポリシー + trigger で十分）。

| 6   | **停止 / 再公開の pet_review_logs 記録**            | Phase 1 推奨: なし                           |

---

## 20. 推奨仕様

| 項目               | 推奨                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| 停止 status        | **`published → paused`**                                                                             |
| 掲載終了           | Phase 1 **対象外**（`family_decided` / `closed` は次フェーズ）                                       |
| 入口 UI            | **BR-10 のみ**                                                                                       |
| RPC                | **`pause_pet_listing`**（+ **`resume_pet_listing`** を同時実装推奨）                                 |
| 改訂審査           | 停止 RPC 内で **`pending_description` クリア + `description_review_status='none'`**（UI で事前告知） |
| 既存 inquiry/visit | **保持**                                                                                             |
| Public View        | **変更なし**                                                                                         |
| ログ               | **なし**                                                                                             |

---

## 21. 結論

犬猫公開停止は **既存 `paused` status + 専用 RPC + trigger 拡張** で最小安全に実装可能。公開 View / inquiry RLS / favorites は **`status='published'` 依存** のため、停止後の非公開化は **追加 View 変更なし** で達成できる。

**ブロッカー:** 再公開（resume）と紹介文審査中停止の product Decision。**停止単体のみ** でも DB/UI は実装可能だが、運用上 **resume セット実装を強く推奨**。

**実装規模: M**（Migration + RPC + trigger + BR-10 UI + テスト。resume 同梱で M 上限）。
