## 1. 現象

Production でブリーダーとして会員登録・メール認証・ログイン後、BR-09 Step 1「基本情報」で **屋号・事業所名** を入力・保存したにもかかわらず、ブリーダー管理画面右上が **「（名称未設定）」** のまま表示される。

### 期待動作

| 状態                       | 表示                   |
| -------------------------- | ---------------------- |
| 屋号・事業所名 未登録      | `（名称未設定）`       |
| 屋号・事業所名 登録済み    | 登録した屋号・事業所名 |
| 屋号空・代表者氏名のみ登録 | 代表者氏名（fallback） |

---

## 2. 原因

### 2.1 直接原因（今回修正対象）

**BR-09 Step 1 保存成功後、ブリーダー layout の Server Component が再実行されず、ヘッダー表示名が古い RSC キャッシュのまま残る。**

| 経路                           | 問題                                                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `src/app/breeder/layout.tsx`   | `loadBreederHeaderDisplayName()` を **初回 SSR 時のみ** 実行                                            |
| `BasicInfoStepForm` 保存成功後 | `router.push()` のみで **`router.refresh()` / `revalidatePath` なし**                                   |
| 結果                           | DB には `business_name` が保存済みでも、layout の `displayName` prop が更新前の `（名称未設定）` のまま |

Next.js App Router では **同一 layout 配下の client 遷移**（例: `/breeder/profile/basic` → `/breeder/profile/location`）で、親 layout の Server Component が自動再フェッチされない場合がある。

### 2.2 副次要因（Production 固有・既に別途対応済み）

2026-09-14 以前の Production では `breeders` への **SELECT / UPDATE GRANT 不足** により、保存・読取の両方が失敗しうる状態だった（`42501 permission denied`）。

| 操作          | GRANT 修正前                                                      | GRANT 修正後（20260914100000 適用済み） |
| ------------- | ----------------------------------------------------------------- | --------------------------------------- |
| Step 1 UPDATE | 失敗しうる（保存エラー表示）                                      | **OK**                                  |
| layout SELECT | 失敗しうる → `getBasicProfileByUserId` が null → `（名称未設定）` | **OK**                                  |

今回の E2E で **「保存して次へ」が成功し Step 2 へ進めている** 場合、GRANT 不足より **layout キャッシュ未更新** が主因と判断する。

### 2.3 除外した原因

| 候補                     | 判定                                                               |
| ------------------------ | ------------------------------------------------------------------ |
| 固定プレースホルダー残存 | **該当せず**（2026-09-01 に「田中 ブリーダー」削除済み）           |
| 誤テーブル参照           | **該当せず**（`breeders.business_name` が正本）                    |
| RLS ポリシー不足         | **該当せず**（`breeders_select_own` / `breeders_update_own` 既存） |
| 別カラム保存             | **該当せず**（Step 1 は `business_name` に保存）                   |

## 3. 参照しているテーブル / カラム

| 用途           | テーブル   | カラム                                                      |
| -------------- | ---------- | ----------------------------------------------------------- |
| ヘッダー表示名 | `breeders` | `business_name`（優先） / `representative_name`（fallback） |
| Step 1 保存    | `breeders` | 上記 + `phone`, `public_email`, `website_url`               |
| Auth 紐付け    | `breeders` | `user_id` = `auth.users.id`                                 |

### 表示コンポーネント

| ファイル                                   | 役割                                                                            |
| ------------------------------------------ | ------------------------------------------------------------------------------- |
| `src/components/layout/breeder-header.tsx` | 右上 `{displayName}` を描画                                                     |
| `src/app/breeder/layout.tsx`               | Server Component。`loadBreederHeaderDisplayName()` を呼び prop 渡し             |
| `src/features/breeder-profile/loaders.ts`  | `requireBreeder()` → `getBasicProfileByUserId()` → `formatBreederDisplayName()` |
| `src/lib/breeder/format.ts`                | 表示名フォーマット（未設定時 `（名称未設定）`）                                 |

### 「（名称未設定）」となる条件（`formatBreederDisplayName`）

1. `business_name` が null / 空 / 空白のみ **かつ**
2. `representative_name` も null / 空 / 空白のみ

いずれか一方でも trim 後非空なら、その値を表示する。

## 4. プロフィール保存処理の確認結果

### Step 1 保存フロー

```
BasicInfoStepForm (client)
  → saveBasicProfile() [server action]
    → updateBasicProfile(userId, { business_name, ... })
      → supabase.from("breeders").update(...).eq("user_id", userId)
```

| 確認項目                   | 結果                                             |
| -------------------------- | ------------------------------------------------ |
| 保存先カラム               | `breeders.business_name` **正しい**              |
| バリデーション             | 屋号・代表者・電話 必須                          |
| 保存失敗時                 | フォームにエラー表示（サイレント失敗ではない）   |
| RLS                        | `breeders_update_own`（`auth.uid() = user_id`）  |
| GRANT（Production 適用後） | authenticated: SELECT / INSERT / UPDATE **あり** |

### ヘッダー取得フロー（保存後）

```
BreederLayout (server)
  → loadBreederHeaderDisplayName()
    → getBasicProfileByUserId(user.id)
      → SELECT business_name, representative_name FROM breeders WHERE user_id = ...
```

**修正前:** 保存後の client 遷移では layout が再実行されず、保存前の表示名が残る。  
**修正後:** `revalidatePath` + `router.refresh()` で layout を再取得。

## 5. 修正内容

### 5.1 `src/features/breeder-profile/service.ts`

`saveBasicProfile` 成功後に layout キャッシュを無効化:

```typescript
revalidatePath("/breeder", "layout");
```

### 5.2 `src/features/breeder-profile/components/basic-info-step-form.tsx`

保存成功後、遷移前に client 側でも RSC を再取得:

```typescript
router.refresh();
router.push(locationPath);
```
