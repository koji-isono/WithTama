## 1. 根本原因（再掲）

`SiteHeader`（`src/components/layout/site-header.tsx`）が **Supabase Auth session / user を一切参照せず**、未ログイン向けリンク（ログイン / 無料会員登録）を **固定表示** していた。

- PU-01 `/pets` は `(public)/layout.tsx` 経由で `SiteHeader` を使用
- buyer 各画面も同じ `SiteHeader` を page 内で配置しており、ログイン後も guest 表示が続いていた
- 認証基盤（`getCurrentBuyer()` / `requireBuyer()` 等）は他機能で正常動作 — **ヘッダーのみ未連動**

---

## 2. 修正内容

### 2.1 方針 A — async Server Component 化

1. **`resolveSiteHeaderNavState(user)`** を新設（`src/features/auth/site-header-nav.ts`）
   - 既存 `isAdminUser()` / `parseMemberUserRole()` を再利用
   - 純関数のため単体テスト可能（auth ロジックの重複なし）
2. **`SiteHeader` を `async function`** に変更
   - Server 側 `createClient()` + `supabase.auth.getUser()`
   - resolver 結果に応じてナビを分岐
3. **既存 `LogoutButton`** を buyer / breeder / admin / role 不明時に再利用
4. **`service_role` / secret は未使用**

### 2.2 buyer 画面への影響

buyer 配下 5 画面（dashboard / profile / favorites / inquiries / visits）は **引き続き `<SiteHeader />` を使用**。

- page 側の変更は **不要**（async Server Component は sync 親から描画可能）
- buyer ログイン済みで各画面を開くと、**マイページ + ログアウト** がヘッダーに表示される（従来の guest 固定表示から改善）

## 3. 表示仕様

| 状態                  | kind                    | ヘッダー表示                                                            |
| --------------------- | ----------------------- | ----------------------------------------------------------------------- |
| 未ログイン            | `guest`                 | 犬猫を探す / **ログイン** / **無料会員登録**                            |
| buyer ログイン済      | `buyer`                 | 犬猫を探す / **マイページ** → `/buyer/dashboard` / **ログアウト**       |
| breeder ログイン済    | `breeder`               | 犬猫を探す / **ダッシュボード** → `/breeder/dashboard` / **ログアウト** |
| admin ログイン済      | `admin`                 | 犬猫を探す / **管理画面** → `/admin` / **ログアウト**                   |
| ログイン済・role 不明 | `authenticated-unknown` | 犬猫を探す / **ログアウト** のみ                                        |

### 3.1 role 不明（`authenticated-unknown`）の設計理由

**guest 扱いにしない理由:**

- Supabase session は有効なのに「ログイン」「無料会員登録」を出すと、**二重ログインや登録導線** となり UX が矛盾する
- 会員種別が判別できない状態で `/buyer/dashboard` 等へ誘導すると、`requireBuyer()` / `requireBreeder()` と **ロール不一致でリダイレクトループや誤遷移** のリスクがある

**採用した安全表示:**

- **犬猫を探す** — 公開閲覧は全員可能
- **ログアウト** — 既存 `LogoutButton` で session をクリアし `/login` へ（再ログイン / サポート問合せの入口）

**想定発生条件:** `user_metadata.role` 未設定・不正値、admin 以外の `app_metadata` 異常等（通常 signup フローでは buyer / breeder が設定される）

**判定順:** admin（`app_metadata.role`）→ buyer / breeder（`user_metadata.role`）→ 上記以外は `authenticated-unknown`
