# 公開ページヘッダー ログイン状態未反映 調査報告

| 項目   | 内容                                                        |
| ------ | ----------------------------------------------------------- |
| 作業日 | 2026-09-17                                                  |
| 種別   | **原因調査・最小修正案（コード変更なし）**                  |
| 環境   | **Production**（https://withtama.jp 想定）                  |
| 現象   | 購入希望者ログイン後も PU-01 ヘッダーが未ログイン表示のまま |

**機密:** ユーザー ID / メール / Cookie 値等の **実値は記載しない**。

**本作業で変更したもの:** **なし**（アプリコード / Migration / Supabase / commit / push 等）

---

## 1. 結論

| 項目             | 判定                                                                                            |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| **根本原因**     | **`SiteHeader` が認証状態を一切参照せず、未ログイン用リンクを固定表示している**                 |
| Production 固有  | **いいえ** — 実装仕様どおりの静的ヘッダー。セッション/Cookie 障害ではない可能性が高い           |
| **最小修正方針** | `SiteHeader` を Server Component 化し、`supabase.auth.getUser()` + ロール判定でナビを切り替える |

## 2. 現象と期待仕様

### 2.1 報告された現象

Production で一般購入希望者として会員登録・ログイン後、PU-01「犬猫を探す」（`/pets`）を開いても、ヘッダーに **「ログイン」「無料会員登録」** が表示されたまま。

### 2.2 期待仕様（ユーザー提示）

| 状態                 | ヘッダー表示                                         |
| -------------------- | ---------------------------------------------------- |
| 未ログイン           | 犬猫を探す / ログイン / 無料会員登録                 |
| 購入希望者ログイン済 | 犬猫を探す / マイページ / ログアウト                 |
| ブリーダーログイン済 | 必要に応じてブリーダーダッシュボード導線             |
| 管理者               | 管理画面側の既存 UI を優先（公開ヘッダーは簡素で可） |

## 9. 根本原因（確度付き）

### 9.1 主因（高確度）— 静的 `SiteHeader`

**`SiteHeader` が Supabase Auth session / user を参照していない。**

根拠:

1. `site-header.tsx` に auth ロジックが存在しない（L3–19）
2. `(public)/layout.tsx` が session を fetch せず `<SiteHeader />` をそのまま描画
3. 設計上 Phase 1 は buyer 専用ヘッダー未整備（BY-01）
4. 同一ヘッダーが `/buyer/*` にも使われており、ログイン後も guest リンクが表示される構造

### 9.2 副次要因（低〜中）— middleware 未実装

長時間放置後の session 切れや refresh 失敗の可能性はあるが、**ログイン直後の PU-01 で guest 表示が続く現象** は主因 9.1 で説明可能。Production 固有の Cookie ドメイン問題の可能性は、buyer 保護ルートが動作していれば低い。

## 10. Production での切り分け手順（推奨）

コード変更なしで **「session 障害 vs ヘッダー未実装」** を確認:

| #   | 操作                                              | 期待（主因 9.1 の場合）                                                |
| --- | ------------------------------------------------- | ---------------------------------------------------------------------- |
| 1   | buyer ログイン後 `/buyer/dashboard` を開く        | ページ本体は表示されるが、ヘッダーは **ログイン / 無料会員登録のまま** |
| 2   | 同セッションで PU-02 を開き、お気に入り UI を確認 | ログイン状態が反映（追加 / 解除 UI が guest と異なる）                 |
| 3   | PU-01 `/pets` を開く                              | ヘッダーは guest のまま（**本報告の現象**）                            |

3 点すべて該当すれば **ヘッダー未連動が確定**。

## 11. 最小修正案（実装は次工程）

**スコープ:** `SiteHeader` の session-aware 化のみ。新規 `BuyerHeader` 全面整備は Phase 2 扱いとする。

### 11.1 方針 A（推奨・最小）— `SiteHeader` を async Server Component 化

1. **`SiteHeader` を `async function SiteHeader()` に変更**
2. **`createClient()` + `supabase.auth.getUser()`** で user 取得
3. **既存 helper を再利用** してロール判定:
   - `isAdminUser(user)` → admin
   - `parseMemberUserRole(user)` → buyer / breeder
4. **ナビ分岐**（期待仕様準拠）:

   | 状態    | 表示                                                                    |
   | ------- | ----------------------------------------------------------------------- |
   | guest   | 犬猫を探す / ログイン / 無料会員登録（現状維持）                        |
   | buyer   | 犬猫を探す / [マイページ → `/buyer/dashboard`] / [`LogoutButton`]       |
   | breeder | 犬猫を探す / [ダッシュボード → `/breeder/dashboard`] / [`LogoutButton`] |
   | admin   | 犬猫を探す / [管理画面 → `/admin`] / [`LogoutButton`]                   |

5. **`LogoutButton` は Client Component のため**、`SiteHeader` 内にそのまま JSX 配置（Server → Client 境界は 1 箇所）

**変更ファイル見込み（最小）:**

- `src/components/layout/site-header.tsx`（主変更）
- （任意）`src/features/auth/` に `getSiteHeaderNavState()` のような 1 関数追加 — ロール判定の重複を避ける

**変更不要（本修正では触らない）:**

- `(public)/layout.tsx` — `SiteHeader` 単体で完結可能
- middleware — 別 PR 推奨
- buyer 各 page の `<SiteHeader />` 重複 — 将来 `(buyer)` layout へ集約可能だが本件スコープ外

### 11.2 方針 B — layout で session fetch して props 渡し

`(public)/layout.tsx` で user / role を 1 回取得し `<SiteHeader nav={...} />` に渡す。

- メリット: fetch 箇所が layout に集約
- デメリット: buyer page が layout 外で独自に `SiteHeader` を描画しているため、**buyer 側も同様の props 渡しが必要**（修正範囲がやや広がる）

→ **方針 A の方が diff が小さい。**

### 11.3 副次改善（任意・別 PR）

- Supabase 推奨の **`middleware.ts`** 追加（session refresh）
- buyer 専用 `BuyerHeader` + layout 集約（BY-01 未決定事項）
