## 0. この手順書について

### 0.1 目的

Production 環境において、運営管理者が **Phase 1 で実装されている管理機能** を安全に運用するための手順を定める。

- ブリーダー審査・犬猫掲載審査の **具体的手順**
- 公開前確認・日次確認の **チェックリスト**
- Stripe / Auth / ログイン障害の **一次切り分け**
- Production で **行ってはいけない操作** の明示

### 0.2 対象環境・対象者

| 項目   | 内容                                           |
| ------ | ---------------------------------------------- |
| 環境   | **Production のみ**（本書の URL はすべて本番） |
| 対象者 | `app_metadata.role = admin` の **運営管理者**  |
| 対象外 | ブリーダー・購入希望者の日常操作（別画面）     |

### 0.3 Phase 1 で管理者ができること / できないこと

#### できること（管理画面 UI）

| 区分           | 画面 ID      | 内容                                                       |
| -------------- | ------------ | ---------------------------------------------------------- |
| ダッシュボード | **AD-00**    | 審査メニューへの導線                                       |
| ブリーダー審査 | **AD-01**    | 審査待ち一覧の確認                                         |
| ブリーダー審査 | **AD-02**    | 審査開始・承認・差戻し・却下、書類プレビュー、審査ログ閲覧 |
| 犬猫掲載審査   | **AD-10**    | 新規掲載・紹介文変更審査の一覧                             |
| 犬猫掲載審査   | **AD-11**    | 承認公開・差戻し、紹介文変更の承認・差戻し、写真・ログ確認 |
| 公開 smoke     | **PU-01/02** | 匿名ブラウザで公開犬猫の表示確認（管理画面外）             |

#### できないこと（Phase 1 未実装 — UI なし）

| 区分                         | 備考                                           |
| ---------------------------- | ---------------------------------------------- |
| 問い合わせ管理               | AD-00 に「今後追加予定」表示。管理 UI **なし** |
| 会員管理                     | 同上                                           |
| 見学管理                     | 管理 UI **なし**                               |
| 課金状況専用一覧             | AD-02 で **参照のみ**                          |
| 犬猫の **強制非公開**        | 管理者 RPC **なし**（ブリーダー BR-10 のみ）   |

| Production DB の直接 UPDATE  | 通常運用 **禁止**（審査は画面 RPC のみ）       |

> **用語:** **RPC**（Remote Procedure Call）— データベース上の審査用関数。管理画面のボタンから呼び出される。

## 1. 管理者ログイン

### 1.1 ログイン手順

| #   | 手順                                                        |
| --- | ----------------------------------------------------------- |
| 1   | ブラウザで **`/login`** を開く                              |
| 2   | 管理者用メール・パスワードでログイン                        |
| 3   | 成功時 **`/admin`**（**AD-00** 管理者ダッシュボード）へ遷移 |

**重要:** **admin 専用ログイン URL は存在しない。** ブリーダー・購入希望者と **同じ `/login`** を使用する。

### 1.2 管理者判定

| 項目     | 内容                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 判定場所 | Supabase Auth の **`app_metadata.role = "admin"`**                       |
| 一般会員 | `user_metadata.role` が `buyer` または `breeder`                         |
| ガード   | 管理画面は **`requireAdmin()`** — admin 以外は `/buyer` 等へリダイレクト |

管理者アカウントの **初回作成** は Supabase Dashboard で Auth ユーザーを作成し `app_metadata` に `role: admin` を設定する（詳細は [Production 初期管理者作成 調査](../09_開発履歴/2026-09-15_Production初期管理者作成_調査報告.md)）。

### 1.3 ログインできない場合の一次確認

| #   | 確認項目                                             | 対処の目安                       |
| --- | ---------------------------------------------------- | -------------------------------- |
| 1   | **メールアドレス**が管理者用か（buyer/breeder 混同） | 正しいアカウントで再試行         |
| 2   | パスワード誤り                                       | リセットまたは Dashboard 確認    |
| 3   | メール **確認済み**（Confirmed）か                   | Supabase Auth → Users            |
| 4   | **`app_metadata.role = admin`** か                   | 未設定なら Dashboard で付与      |
| 5   | buyer/breeder としてログインしていないか             | ログアウト後 `/login` から再実行 |

**エスカレーション:** 上記で解決しない場合、**Auth ユーザーの削除・再作成は行わず** [§11 エスカレーション](#11-エスカレーション) へ。

## 3. ブリーダー審査

### 3.1 画面・URL

| 画面 ID   | URL                                   | 用途           |
| --------- | ------------------------------------- | -------------- |
| **AD-01** | `/admin/breeders/reviews`             | 審査一覧       |
| **AD-02** | `/admin/breeders/reviews/[breederId]` | 審査詳細・操作 |

`[breederId]` は UUID（画面から遷移。手入力不要）。

### 3.2 審査フロー概要

```
申請済み / 差戻し（再提出）
    → [審査開始] start_breeder_review
審査中 (under_review)
    → [承認] approve_breeder_review → 承認済み
    → [差戻し] return_breeder_review（コメント必須）→ 差戻し
    → [却下] reject_breeder_review（コメント必須）→ 却下
```

### 3.3 操作手順（AD-02）

| #   | 手順                                                                        |
| --- | --------------------------------------------------------------------------- |
| 1   | **AD-01** で審査対象を選び **AD-02** を開く                                 |
| 2   | ステータスが **申請済み** または **差戻し（再提出）** の場合 → **審査開始** |
| 3   | **基本情報** — 屋号、代表者名、電話、公開メール、Web                        |
| 4   | **所在地** — 郵便番号、都道府県、市区町村、番地                             |
| 5   | **本人確認書類** — プレビュー（Signed URL、**有効 300 秒**）                |
| 6   | **第一種動物取扱業登録証** — プレビュー                                     |
| 7   | **登録情報** — 種別、番号、自治体、**有効期限**（期限切れは承認不可）       |
| 8   | **プロフィール** — 紹介、繁殖方針、健康管理方針、飼育環境（目視）           |
| 9   | **課金（参考）** — 会員状態・Subscription 状態（**参照のみ**）              |
| 10  | **審査ログ** — 過去の申請・開始・承認・差戻し・却下を確認                   |
| 11  | 問題なければ **承認** / 修正要請なら **差戻し** / 不可なら **却下**         |

### 3.4 法的判断について（必読）

管理画面（AD-02）には次の注記が表示される:

> **弁護士または管轄自治体への確認が必要です。システムは書類の法的適否を自動判定しません。**

| 項目           | 内容                                             |
| -------------- | ------------------------------------------------ |
| システムの役割 | 書類 **存在確認**・申請内容 **表示**・状態遷移   |
| 管理者の役割   | 目視確認・**法的適否の最終判断**（外部確認含む） |
| 本書の立場     | **法的適否を断定しない**                         |

### 3.5 承認条件（RPC `approve_breeder_review`）

**すべて満たさないと承認ボタンは RPC エラーになる。**

| #   | 条件                                                                |
| --- | ------------------------------------------------------------------- |
| A1  | `review_status = under_review`（審査開始済み）                      |
| A2  | `identity_document_path` が **非空**                                |
| A3  | `business_license_path` が **非空**                                 |
| A4  | `registration_expires_at` が **非 NULL** かつ **今日以降**          |
| A5  | Storage **`breeder-documents`** に本人確認書類オブジェクト **存在** |
| A6  | Storage **`breeder-documents`** に登録証オブジェクト **存在**       |

**承認時の副作用:**

| 更新される項目                        | 更新されない項目                                         |
| ------------------------------------- | -------------------------------------------------------- |
| `review_status → approved`            | **`membership_status`**（課金開始まで pending 等のまま） |
| 本人/登録証 verification → `verified` | Stripe 関連列                                            |
| `approved_at` 設定                    |                                                          |

> UI 注記: **「承認後も月額課金が開始されるまでは利用開始状態にはなりません。」**

### 3.6 差戻し・却下

| 操作   | 必須入力         | 遷移先                  | verification 列 |
| ------ | ---------------- | ----------------------- | --------------- |
| 差戻し | **コメント必須** | `resubmission_required` | 変更なし        |
| 却下   | **コメント必須** | `rejected`              | 変更なし        |

### 3.7 承認後にブリーダーができること

| 内容           | 条件・備考                                                  |
| -------------- | ----------------------------------------------------------- |
| 犬猫登録       | BR-07/08/10 等（ブリーダー審査 **approved**）               |
| 月額課金開始   | BR-13 Checkout（**別途** Stripe 決済）                      |
| 犬猫の一般公開 | **AD-10/11 審査** + **`membership_status = active`** が必要 |

## 4. 犬猫掲載審査

### 4.1 画面・URL

| 画面 ID   | URL                           | 用途           |
| --------- | ----------------------------- | -------------- |
| **AD-10** | `/admin/pets/reviews`         | 審査一覧       |
| **AD-11** | `/admin/pets/reviews/[petId]` | 審査詳細・操作 |

一覧の種別ラベル: **新規掲載** / **紹介文変更**。

### 4.2 新規掲載審査

| 段階     | 操作者     | 操作                       | ステータス       |
| -------- | ---------- | -------------------------- | ---------------- |
| 登録     | ブリーダー | BR-10 登録・写真           | `draft`          |
| 公開申請 | ブリーダー | 公開申請                   | → `under_review` |
| 内容確認 | 管理者     | AD-11 で項目・**写真**確認 | —                |
| 承認     | 管理者     | **承認して公開**           | → `published`    |
| 差戻し   | 管理者     | 差戻し（**コメント必須**） | → `draft`        |

**承認 RPC（`approve_pet_for_publish`）の追加条件:**

| #   | 条件                                               |
| --- | -------------------------------------------------- |
| P1  | 犬猫 `status = under_review`                       |
| P2  | 所属ブリーダー `review_status = approved`          |
| P3  | 本人確認 `identity_verification_status = verified` |
| P4  | 登録証 `business_verification_status = verified`   |
| P5  | `registration_expires_at` が **今日以降**          |

> **一般公開（PU-01/02）にさらに必要:** ブリーダー **`membership_status = active`**（§5 参照）。

### 4.3 公開後・紹介文変更審査

| 段階       | 操作                           | 備考                                           |
| ---------- | ------------------------------ | ---------------------------------------------- |
| ブリーダー | 公開中犬猫の紹介文変更を申請   | `description_review_status → under_review`     |
| AD-10      | 種別 **「紹介文変更」** で表示 | `status` は **`published` のまま**             |
| 管理者     | **承認** / **差戻し**          | 承認で `description` 更新、差戻しで `returned` |

### 4.4 公開停止について（管理者は操作不可）

> ### ⚠ Phase 1 重要制約
>
> **管理者による犬猫の強制非公開（pause / unpublish）は Phase 1 ではできません。**
>
> - 公開停止は **ブリーダー本人** が **BR-10** から **`pause_pet_listing`** のみ実行可能
> - 緊急時は **ブリーダーへの連絡** が必要（強制停止 RPC は第2期検討 — [未決定事項](#未決定事項) U3）

## 5. 課金・Stripe 確認

### 5.1 データの流れ（管理者向け概要）

```
ブリーダー BR-13「月額会費のお支払いへ」
    ↓
POST /api/billing/checkout
    ↓
Stripe Checkout（サブスクリプション）
    ↓
決済成功
    ↓
Stripe Webhook → POST /api/webhooks/stripe
    ↓
service_role: stripe_webhook_events（冪等記録）
    ↓
service_role: breeders 課金列 UPDATE
    ↓
membership_status = active（等）
    ↓
BR-13 UI「利用中」
```

| 用語                  | 説明                                             |
| --------------------- | ------------------------------------------------ |
| **Checkout**          | Stripe の決済画面。ブリーダーが BR-13 から開始   |
| **Webhook**           | Stripe から WithTama サーバーへの決済通知        |
| **service_role**      | サーバー内部専用 DB 権限（管理者画面では不使用） |
| **membership_status** | 会員利用状態（`active` で一般公開条件を満たす）  |

**月額会費:** 5,000 円（**税抜**）+ Stripe Tax Rate（BR-13 / 画面表示は税抜統一）。

### 5.2 管理者の確認方法（Phase 1）

| 方法                 | 内容                                                                |
| -------------------- | ------------------------------------------------------------------- |
| **AD-02**            | `membership_status` / `subscription_status` **ラベル参照のみ**      |
| **Stripe Dashboard** | Customer / Subscription / Payments / Webhooks（**正**）             |
| **ブリーダー依頼**   | 当事者に **BR-13**（`/breeder/billing`）のスクリーンショット確認    |
| Supabase             | `breeders` 課金列 — **読取のみ**（Production **直接 UPDATE 禁止**） |

> **Phase 1 に管理者専用の「課金一覧」画面は存在しません。**

## 6. Stripe 障害対応

### 6.1 復旧の原則

| 原則  | 内容                                                                                                      |
| ----- | --------------------------------------------------------------------------------------------------------- |
| **1** | **`breeders.membership_status` 等の課金列を Production DB で手動変更しない**（Trigger 拒否 + 監査リスク） |
| **2** | 原因（env / Webhook / DB 権限）を **修正** したうえで、Stripe Dashboard から **対象イベントを再送**       |
| **3** | Vercel **Production Redeploy** が必要な env 変更はデプロイ完了を確認                                      |

### 6.2 症状別チェックリスト

#### Checkout 500（BR-13 から決済開始できない）

| #   | 確認項目                                                 | 見る場所                       |
| --- | -------------------------------------------------------- | ------------------------------ |
| C1  | Vercel Logs — `/api/billing/checkout`                    | Vercel → Logs                  |
| C2  | `STRIPE_SECRET_KEY` が **`sk_live_...` 形式** か         | Vercel → Environment Variables |
| C3  | Secret Key スロットに **Price ID が入っていないか**      | 同上                           |
| C4  | `STRIPE_BREEDER_PRICE_ID` / `STRIPE_BREEDER_TAX_RATE_ID` | 同上                           |
| C5  | env 変更後 **Production Redeploy** 済みか                | Vercel → Deployments           |
| C6  | ブリーダー `review_status = approved` か                 | AD-02                          |

#### Webhook 400

| #   | 確認項目                                 | 見る場所                  |
| --- | ---------------------------------------- | ------------------------- |
| W1  | `STRIPE_WEBHOOK_SECRET` が Stripe と一致 | Vercel + Stripe Dashboard |
| W2  | Webhook URL が Production ドメインか     | Stripe → Webhooks         |

#### Webhook 500

| #   | 確認項目                                       | 見る場所 / 典型ログ                                            |
| --- | ---------------------------------------------- | -------------------------------------------------------------- |
| W3  | Vercel Logs — HTTP 500、`postgrestCode: 42501` | `stripe_webhook_events` INSERT 失敗（service_role GRANT 不足） |
| W4  | `breeder lookup` 失敗                          | `breeders` への service_role SELECT/UPDATE 不足                |
| W5  | Migration **37 本** Local/Remote 一致          | `supabase migration list`（開発担当）                          |
| W6  | 修正後 **Stripe Dashboard でイベント再送**     | Events → 対象 → Resend                                         |

#### 支払い済みなのに BR-13 が「利用中」にならない

| #   | 確認項目                                           | 見る場所             |
| --- | -------------------------------------------------- | -------------------- |
| B1  | Stripe Checkout **成功** しているか                | Stripe → Payments    |
| B2  | Webhook 配信が **200** か（失敗履歴がないか）      | Stripe → Webhooks    |
| B3  | `stripe_webhook_events` に該当イベント ID があるか | Supabase（読取のみ） |
| B4  | Session metadata に **`breeder_id`** があるか      | Stripe Session 詳細  |
| B5  | 上記 OK なら **イベント再送** → 再確認             | Stripe Dashboard     |

#### env 変更後に反映されない

| #   | 確認項目                                                       |
| --- | -------------------------------------------------------------- |
| E1  | Vercel **Production** 環境に設定したか（Preview だけではない） |
| E2  | 変更後 **Redeploy** したか                                     |
| E3  | デプロイ完了後に BR-13 / Webhook を再テスト                    |

## 10. Production 操作禁止事項

> ### ⛔ Production 通常運用で禁止
>
> 以下は **いずれも禁止**。疑問がある場合は **実行前に** [§11](#11-エスカレーション) へ。

| #    | 禁止操作                                                           | 理由（要約）                           |
| ---- | ------------------------------------------------------------------ | -------------------------------------- |
| ⛔1  | **Auth user** を安易に **削除・再作成**                            | FK RESTRICT、Stripe / 業務 ID 不整合   |
| ⛔2  | **`breeders` / `buyers` 行の DELETE**                              | FK 連鎖、Stripe 連携破壊               |
| ⛔3  | **Stripe Customer** の削除                                         | Portal / 再課金不能、会計証跡          |
| ⛔4  | **Subscription** の無理解キャンセル                                | 公開犬猫・会員状態への影響             |
| ⛔5  | **`stripe_webhook_events` の DELETE**                              | Webhook **二重処理** リスク            |
| ⛔6  | **Production TRUNCATE / 一括 DELETE SQL**                          | 復旧不能                               |
| ⛔7  | **課金列**（`membership_status`, `stripe_*` 等）の **直接 UPDATE** | Trigger 42501 + 監査                   |
| ⛔8  | **`pets` ハード DELETE**                                           | inquiries / visits / 監査ログ RESTRICT |
| ⛔9  | **service_role key** のクライアント利用・共有・画面表示            | 全 RLS bypass                          |
| ⛔10 | 管理者による犬猫 **強制 pause / unpublish**                        | Phase 1 **RPC 未実装**                 |
| ⛔11 | FK を無視した削除順序の SQL                                        | RESTRICT エラーまたはデータ破損        |

**原則:** 状態変更は **管理画面の審査 RPC** または **Stripe Webhook** のみ。それ以外の Production DB 直接変更は **開発担当の明示指示** がある場合を除き行わない。
